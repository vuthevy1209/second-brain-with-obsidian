# Java Exception Handling

## What is an Exception?

An **exception** is an event that disrupts the normal flow of program execution. In Java, exceptions are objects — instances of `Throwable` and its subclasses.

```
Throwable
  ├── Error           (serious JVM errors — do NOT catch these)
  │     ├── OutOfMemoryError
  │     ├── StackOverflowError
  │     └── VirtualMachineError
  └── Exception       (program-level problems — handle these)
        ├── RuntimeException         (Unchecked)
        │     ├── NullPointerException
        │     ├── ArrayIndexOutOfBoundsException
        │     ├── IllegalArgumentException
        │     ├── ClassCastException
        │     └── ArithmeticException
        └── IOException              (Checked)
              ├── FileNotFoundException
              └── SQLException
```

## Checked vs Unchecked Exceptions

| Type | Definition | Must handle? | Examples |
|------|-----------|-------------|---------|
| **Checked** | Subclasses of `Exception` (not `RuntimeException`) | Yes — compile error if not handled | `IOException`, `SQLException` |
| **Unchecked** | Subclasses of `RuntimeException` | No | `NullPointerException`, `IllegalArgumentException` |
| **Error** | Subclasses of `Error` | No — should not catch | `OutOfMemoryError` |

## try-catch-finally

```java
try {
    // Code that might throw an exception
    int result = 10 / 0;
} catch (ArithmeticException e) {
    // Handle specific exception
    System.out.println("Cannot divide by zero: " + e.getMessage());
} catch (Exception e) {
    // Catch-all for other exceptions (more general last)
    System.out.println("Unexpected error: " + e.getMessage());
} finally {
    // Always executes — used for cleanup
    System.out.println("This always runs");
}
```

**Key rules:**
- More specific exceptions must appear before more general ones
- `finally` always runs — even if an exception occurs, or `return` is called in `try`/`catch`
- `finally` is skipped only by `System.exit()` or JVM crash

## Multi-catch (Java 7+)

Handle multiple exception types with a single catch block:

```java
try {
    // ...
} catch (IOException | SQLException e) {
    System.out.println("IO or SQL error: " + e.getMessage());
}
```

In a multi-catch, the variable `e` is effectively `final` — you cannot reassign it.

## try-with-resources (Java 7+)

Automatically closes resources that implement `AutoCloseable`. Eliminates the need for `finally` blocks for cleanup.

```java
// Before Java 7 — verbose
BufferedReader br = null;
try {
    br = new BufferedReader(new FileReader("file.txt"));
    String line = br.readLine();
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (br != null) br.close();
}

// Java 7+ — clean and safe
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) {
    String line = br.readLine();
} catch (IOException e) {
    e.printStackTrace();
}
// br.close() is called automatically

// Multiple resources
try (
    Connection conn = DriverManager.getConnection(url);
    PreparedStatement stmt = conn.prepareStatement(sql)
) {
    // ...
}
```

Resources are closed in **reverse** order of declaration. Exceptions from `close()` are suppressed if an exception was already thrown from the `try` block.

## Throwing Exceptions

```java
public void setAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("Age cannot be negative: " + age);
    }
    this.age = age;
}

// Declaring checked exceptions
public void readFile(String path) throws IOException {
    // ...
}

// Re-throwing
try {
    doSomething();
} catch (IOException e) {
    throw new RuntimeException("Failed to do something", e); // wrap with cause
}
```

## Creating Custom Exceptions

```java
// Checked custom exception
public class InsufficientFundsException extends Exception {
    private double amount;

    public InsufficientFundsException(double amount) {
        super("Insufficient funds. Need: " + amount);
        this.amount = amount;
    }

    public double getAmount() {
        return amount;
    }
}

// Unchecked custom exception
public class InvalidOrderException extends RuntimeException {
    public InvalidOrderException(String message) {
        super(message);
    }

    public InvalidOrderException(String message, Throwable cause) {
        super(message, cause);
    }
}
```

**Best practice**: Prefer unchecked exceptions for programming errors (invalid args, null, etc.). Use checked exceptions only when the caller can reasonably recover (e.g., file not found — could ask user for new path).

## Exception Methods

```java
try {
    // ...
} catch (Exception e) {
    e.getMessage()           // short error message
    e.toString()             // class name + message
    e.printStackTrace()      // full stack trace to stderr
    e.getCause()             // the wrapped/underlying exception
    e.getClass().getName()   // fully qualified class name
    e.getStackTrace()        // StackTraceElement[]
}
```

## Exception Chaining

Preserving the original exception when wrapping:

```java
try {
    // low-level operation
    connect();
} catch (IOException e) {
    // wrap with context, preserve original as cause
    throw new ServiceException("Failed to connect to service", e);
}

// Later when catching ServiceException:
catch (ServiceException e) {
    Throwable cause = e.getCause(); // gets the original IOException
}
```

## Best Practices

**Catch specific, not general**
```java
// Bad
catch (Exception e) { ... }

// Good
catch (FileNotFoundException e) { ... }
catch (IOException e) { ... }
```

**Never swallow exceptions silently**
```java
// Very Bad — exception disappears
catch (Exception e) { }

// Acceptable minimum
catch (Exception e) {
    log.error("Unexpected error", e);
    throw e; // re-throw if needed
}
```

**Use finally or try-with-resources for cleanup**
```java
// Always release external resources
try (InputStream in = new FileInputStream(file)) {
    process(in);
}
```

**Provide context when throwing**
```java
throw new IllegalArgumentException(
    "Expected positive amount, got: " + amount + " for order: " + orderId
);
```

**Prefer runtime exceptions for unrecoverable errors**
- If the caller cannot realistically do anything about an exception, use `RuntimeException`
- Reserve checked exceptions for truly recoverable situations

## `StackOverflowError` and Recursion

```java
// Causes StackOverflowError (not a typo — it's an Error, not Exception)
public int factorial(int n) {
    return n * factorial(n - 1); // missing base case
}
```
