# Java Collections Framework

## Overview

The **Java Collections Framework (JCF)** provides a unified architecture for storing and manipulating groups of objects. It consists of:

- **Interfaces** — abstract data types (`List`, `Set`, `Map`, `Queue`, etc.)
- **Implementations** — concrete classes (`ArrayList`, `HashMap`, `TreeSet`, etc.)
- **Algorithms** — utility methods in `Collections` and `Arrays`

```
Iterable
  └── Collection
        ├── List
        │     ├── ArrayList
        │     ├── LinkedList
        │     └── Vector / Stack (legacy)
        ├── Set
        │     ├── HashSet
        │     ├── LinkedHashSet
        │     └── TreeSet
        └── Queue
              ├── LinkedList
              ├── PriorityQueue
              └── Deque
                    ├── ArrayDeque
                    └── LinkedList

Map (separate hierarchy)
  ├── HashMap
  ├── LinkedHashMap
  ├── TreeMap
  └── Hashtable (legacy)
```

## List

`List` is an **ordered, index-based** collection that allows duplicates.

### ArrayList

- Backed by a dynamic array
- Fast random access: O(1)
- Slow insertion/deletion at middle: O(n)
- Not thread-safe

```java
List<String> list = new ArrayList<>();
list.add("Alice");
list.add("Bob");
list.add(1, "Charlie");    // insert at index
list.get(0);               // "Alice"
list.set(0, "Alex");       // replace at index
list.remove(0);            // remove by index
list.remove("Bob");        // remove by value
list.size();               // 2
list.contains("Charlie");  // true
list.indexOf("Charlie");   // 0

// Iterate
for (String s : list) { ... }
list.forEach(System.out::println);

// Sort
Collections.sort(list);
list.sort(Comparator.naturalOrder());
list.sort(Comparator.reverseOrder());

// Sub-list (view, not copy)
List<String> sub = list.subList(0, 2);
```

### LinkedList

- Backed by a doubly-linked list
- Fast insertion/deletion at ends: O(1)
- Slow random access: O(n)
- Implements both `List` and `Deque`

```java
LinkedList<String> ll = new LinkedList<>();
ll.addFirst("A");
ll.addLast("B");
ll.peekFirst();   // view head without removing
ll.pollFirst();   // remove and return head
ll.peekLast();
ll.pollLast();
```

### Choosing ArrayList vs LinkedList

| Operation | ArrayList | LinkedList |
|-----------|-----------|------------|
| `get(i)` | O(1) | O(n) |
| `add(end)` | O(1) amortized | O(1) |
| `add(middle)` | O(n) | O(n) find + O(1) insert |
| `remove(middle)` | O(n) | O(n) find + O(1) remove |
| Memory overhead | Low | High (node pointers) |

**In practice, use `ArrayList` by default.** Use `LinkedList` only when frequent head/tail insertion/removal is needed.

## Set

`Set` is a collection that **does not allow duplicates**.

### HashSet

- Backed by a `HashMap`
- No guaranteed order
- O(1) average for `add`, `remove`, `contains`

```java
Set<String> set = new HashSet<>();
set.add("Apple");
set.add("Banana");
set.add("Apple");    // ignored, already present
set.size();          // 2
set.contains("Apple"); // true
set.remove("Apple");
```

### LinkedHashSet

- Like `HashSet` but maintains **insertion order**

```java
Set<String> linked = new LinkedHashSet<>();
linked.add("C");
linked.add("A");
linked.add("B");
// Iteration order: C, A, B
```

### TreeSet

- Backed by a **Red-Black Tree**
- Elements are **sorted** (natural order or custom `Comparator`)
- O(log n) for `add`, `remove`, `contains`

```java
TreeSet<Integer> tree = new TreeSet<>();
tree.add(5);
tree.add(1);
tree.add(3);
// Iteration: 1, 3, 5

tree.first();           // 1
tree.last();            // 5
tree.floor(4);          // 3 (greatest ≤ 4)
tree.ceiling(4);        // 5 (smallest ≥ 4)
tree.headSet(3);        // {1} (strictly less than 3)
tree.tailSet(3);        // {3, 5} (3 and above)
tree.subSet(1, 4);      // {1, 3}
```

## Map

`Map` stores **key-value pairs**. Keys are unique.

### HashMap

- Key-value pairs with no guaranteed order
- O(1) average for `put`, `get`, `remove`
- Allows one `null` key and multiple `null` values

```java
Map<String, Integer> map = new HashMap<>();
map.put("Alice", 90);
map.put("Bob", 85);
map.put("Alice", 95);  // overwrites existing value

map.get("Alice");          // 95
map.getOrDefault("Eve", 0); // 0 (key not present)
map.containsKey("Bob");    // true
map.containsValue(85);     // true
map.remove("Bob");
map.size();                // 1

// Iteration
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println(entry.getKey() + " → " + entry.getValue());
}
map.keySet();    // Set of keys
map.values();    // Collection of values
map.entrySet();  // Set of key-value pairs

// Java 8+ operations
map.putIfAbsent("Carol", 88);
map.computeIfAbsent("Dave", k -> k.length());
map.merge("Alice", 5, Integer::sum); // adds 5 to Alice's score
map.forEach((k, v) -> System.out.println(k + ": " + v));
```

### LinkedHashMap

- Maintains **insertion order** of keys
- Useful for implementing LRU cache (via `accessOrder` constructor)

```java
Map<String, Integer> linked = new LinkedHashMap<>();
// or for LRU behavior:
Map<String, Integer> lru = new LinkedHashMap<>(16, 0.75f, true); // accessOrder=true
```

### TreeMap

- Keys are **sorted** (natural order or `Comparator`)
- O(log n) operations
- Implements `NavigableMap`

```java
TreeMap<String, Integer> tree = new TreeMap<>();
tree.put("banana", 2);
tree.put("apple", 1);
tree.put("cherry", 3);

tree.firstKey();          // "apple"
tree.lastKey();           // "cherry"
tree.floorKey("ba");      // "apple"
tree.ceilingKey("ba");    // "banana"
tree.headMap("cherry");   // {apple=1, banana=2}
tree.tailMap("banana");   // {banana=2, cherry=3}
```

## Queue and Deque

### Queue

FIFO data structure. Key interface methods:

| Method | Throws exception | Returns null/false |
|--------|-----------------|-------------------|
| Insert | `add(e)` | `offer(e)` |
| Remove | `remove()` | `poll()` |
| Examine | `element()` | `peek()` |

```java
Queue<String> queue = new LinkedList<>();
queue.offer("First");
queue.offer("Second");
queue.peek();   // "First" (no remove)
queue.poll();   // "First" (removes)
```

### PriorityQueue

- Elements ordered by natural order or custom `Comparator`
- Head is always the smallest (min-heap by default)

```java
PriorityQueue<Integer> pq = new PriorityQueue<>();
pq.offer(5);
pq.offer(1);
pq.offer(3);
pq.poll();  // 1 (smallest)

// Max-heap
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());
```

### Deque (Double-Ended Queue)

```java
Deque<String> deque = new ArrayDeque<>();
deque.addFirst("A");   deque.addLast("B");
deque.peekFirst();     deque.peekLast();
deque.pollFirst();     deque.pollLast();
// Used as stack: push()/pop()/peek()
// Used as queue: offer()/poll()/peek()
```

## The `Collections` Utility Class

```java
List<Integer> list = new ArrayList<>(Arrays.asList(3, 1, 4, 1, 5, 9));

Collections.sort(list);                      // [1, 1, 3, 4, 5, 9]
Collections.sort(list, Comparator.reverseOrder()); // [9, 5, 4, 3, 1, 1]
Collections.reverse(list);
Collections.shuffle(list);
Collections.min(list);                       // 1
Collections.max(list);                       // 9
Collections.frequency(list, 1);             // 2
Collections.binarySearch(sorted, 4);        // index
Collections.fill(list, 0);                  // all zeros
Collections.nCopies(5, "x");               // ["x","x","x","x","x"]

// Unmodifiable wrappers
List<String> immutable = Collections.unmodifiableList(list);
Set<String> immutableSet = Collections.unmodifiableSet(set);

// Thread-safe wrappers
List<String> synced = Collections.synchronizedList(list);
```

## Immutable Collections (Java 9+)

```java
List<String> immList = List.of("a", "b", "c");    // throws on modification
Set<String> immSet = Set.of("x", "y", "z");
Map<String, Integer> immMap = Map.of("a", 1, "b", 2);
Map<String, Integer> immMap2 = Map.ofEntries(
    Map.entry("a", 1),
    Map.entry("b", 2)
);
```

## Choosing the Right Collection

| Need | Use |
|------|-----|
| Ordered list with index access | `ArrayList` |
| Frequent head/tail add/remove | `ArrayDeque` |
| No duplicates, unordered | `HashSet` |
| No duplicates, insertion order | `LinkedHashSet` |
| No duplicates, sorted | `TreeSet` |
| Key-value, unordered | `HashMap` |
| Key-value, insertion order | `LinkedHashMap` |
| Key-value, sorted by key | `TreeMap` |
| Priority/min-heap | `PriorityQueue` |
| Thread-safe operations | `ConcurrentHashMap`, `CopyOnWriteArrayList` |

## Generics with Collections

Always use generics to enforce type safety at compile time:

```java
List list = new ArrayList();  // raw type — avoid
list.add("hello");
list.add(42);                 // no compile error, but unsafe

List<String> typed = new ArrayList<>(); // generic — preferred
typed.add("hello");
// typed.add(42);             // compile error — caught early
```
