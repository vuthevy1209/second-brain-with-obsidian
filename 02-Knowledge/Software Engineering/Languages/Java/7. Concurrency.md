# Java Concurrency

## Basics of Threads

A **thread** is the smallest unit of execution in a Java program. The JVM starts with a main thread. You can create additional threads for parallel work.

### Creating Threads

**Way 1: Extend `Thread`**

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Running in: " + Thread.currentThread().getName());
    }
}

MyThread t = new MyThread();
t.start(); // starts a new thread (do NOT call run() directly)
```

**Way 2: Implement `Runnable`** (preferred — allows extending another class)

```java
class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("Task running");
    }
}

Thread t = new Thread(new MyTask());
t.start();

// Lambda (Java 8+)
Thread t2 = new Thread(() -> System.out.println("Lambda task"));
t2.start();
```

## Thread Lifecycle

```
NEW → RUNNABLE → (RUNNING) → TERMINATED
                     ↕
              BLOCKED/WAITING/TIMED_WAITING
```

| State | Description |
|-------|-------------|
| `NEW` | Created, not yet started |
| `RUNNABLE` | Ready to run or running |
| `BLOCKED` | Waiting to acquire a monitor lock |
| `WAITING` | Waiting indefinitely (e.g., `wait()`, `join()`) |
| `TIMED_WAITING` | Waiting with timeout (`sleep()`, `wait(millis)`) |
| `TERMINATED` | Finished execution |

## Thread Methods

```java
Thread t = new Thread(() -> { ... });
t.start();
t.join();            // waits for t to finish
t.join(1000);        // waits up to 1000ms
t.interrupt();       // signals the thread to stop
t.isAlive();         // true if running
t.getName();
t.setName("worker-1");
t.getPriority();     // 1 (MIN) to 10 (MAX), default 5
t.setPriority(Thread.MAX_PRIORITY);
t.setDaemon(true);   // daemon thread — JVM exits when only daemons remain

Thread.sleep(500);         // pause current thread (throws InterruptedException)
Thread.currentThread();    // reference to the running thread
Thread.yield();            // hint to scheduler to give up CPU
```

## `synchronized` — Mutual Exclusion

The `synchronized` keyword ensures only one thread can enter a block at a time:

```java
public class Counter {
    private int count = 0;

    // synchronized method — locks on `this`
    public synchronized void increment() {
        count++;
    }

    // synchronized block — finer-grained control
    public void add(int n) {
        synchronized (this) {
            count += n;
        }
    }

    // static synchronized — locks on the Class object
    private static int total = 0;
    public static synchronized void addToTotal(int n) {
        total += n;
    }
}
```

## `volatile`

Guarantees **visibility**: changes made by one thread are immediately visible to all others. Does **not** guarantee atomicity for compound operations.

```java
class Worker implements Runnable {
    private volatile boolean running = true;

    public void stop() { running = false; }

    @Override
    public void run() {
        while (running) {
            // do work
        }
    }
}
```

## `wait()` / `notify()` / `notifyAll()`

Low-level inter-thread communication. Must be called inside `synchronized` block:

```java
class SharedQueue {
    private final List<Integer> queue = new ArrayList<>();

    public synchronized void produce(int item) throws InterruptedException {
        while (queue.size() >= 10) {
            wait(); // release lock, wait for space
        }
        queue.add(item);
        notifyAll(); // wake up consumers
    }

    public synchronized int consume() throws InterruptedException {
        while (queue.isEmpty()) {
            wait(); // release lock, wait for items
        }
        int item = queue.remove(0);
        notifyAll(); // wake up producers
        return item;
    }
}
```

## ExecutorService (High-Level Threading)

The `java.util.concurrent` package provides higher-level tools.

```java
// Fixed thread pool
ExecutorService executor = Executors.newFixedThreadPool(4);

// Submit Runnable (no result)
executor.submit(() -> System.out.println("Task"));

// Submit Callable (returns result via Future)
Future<Integer> future = executor.submit(() -> {
    Thread.sleep(1000);
    return 42;
});

int result = future.get();          // blocks until done
int r2 = future.get(2, TimeUnit.SECONDS); // blocks with timeout
future.isDone();                    // check without blocking
future.cancel(true);                // attempt to cancel

// Shutdown gracefully
executor.shutdown();               // no new tasks, waits for running ones
executor.shutdownNow();            // attempts to stop all running tasks
executor.awaitTermination(5, TimeUnit.SECONDS);
```

### Common Executor Types

```java
Executors.newFixedThreadPool(n)         // n threads, reused
Executors.newCachedThreadPool()         // grows as needed, idle threads expire after 60s
Executors.newSingleThreadExecutor()     // 1 thread — sequential execution
Executors.newScheduledThreadPool(n)     // delayed/periodic tasks
```

## Atomic Classes

`java.util.concurrent.atomic` — thread-safe operations without `synchronized`:

```java
AtomicInteger counter = new AtomicInteger(0);
counter.incrementAndGet();     // atomic ++
counter.decrementAndGet();     // atomic --
counter.getAndAdd(5);          // atomic += 5
counter.compareAndSet(5, 10);  // if current == 5, set to 10

AtomicBoolean flag = new AtomicBoolean(false);
AtomicReference<String> ref = new AtomicReference<>("initial");
```

## Locks (java.util.concurrent.locks)

More flexible than `synchronized`:

```java
ReentrantLock lock = new ReentrantLock();

lock.lock();
try {
    // critical section
} finally {
    lock.unlock(); // always unlock in finally
}

// Trylock — non-blocking
if (lock.tryLock()) {
    try {
        // got the lock
    } finally {
        lock.unlock();
    }
} else {
    // could not acquire lock
}

// ReadWriteLock — multiple readers, one writer
ReadWriteLock rwLock = new ReentrantReadWriteLock();
rwLock.readLock().lock();   // multiple threads can hold read lock
rwLock.writeLock().lock();  // exclusive write lock
```

## Concurrent Collections

Thread-safe alternatives to standard collections:

| Standard | Concurrent Alternative |
|----------|----------------------|
| `HashMap` | `ConcurrentHashMap` |
| `ArrayList` | `CopyOnWriteArrayList` |
| `HashSet` | `CopyOnWriteArraySet` |
| `LinkedList` (as queue) | `ConcurrentLinkedQueue` |
| — | `BlockingQueue` (ArrayBlockingQueue, LinkedBlockingQueue) |

```java
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
map.put("key", 1);
map.computeIfAbsent("other", k -> 0);

BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(10);
queue.put(1);     // blocks if full
queue.take();     // blocks if empty
```

## Common Concurrency Issues

**Race Condition** — Two threads access shared data concurrently and the result depends on timing. Fix: use `synchronized`, `Lock`, or atomic classes.

**Deadlock** — Two threads each hold a lock the other needs. Fix: always acquire locks in the same order; use `tryLock()` with timeout.

**Livelock** — Threads keep responding to each other without making progress. Fix: introduce random back-off or priority.

**Starvation** — A thread never gets CPU time. Fix: use fair locks (`new ReentrantLock(true)`).
