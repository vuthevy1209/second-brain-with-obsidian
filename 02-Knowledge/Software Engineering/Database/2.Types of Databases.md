### **1. Relational Databases (SQL-Based)**

![[2.Types of Databases-1779628362955.webp]]

Relational databases are the most widely used, especially for systems requiring strong consistency and structured data.

- Structure: Data is stored in tables (relations) with rows and columns.
- Example Tools: MySQL, PostgreSQL, Oracle Database, SQL Server.
- Ideal For: Financial systems, inventory management, CRM platforms.
- Query Language: SQL (Structured Query Language) to query data.
- Strengths: Strong data integrity, schema enforcement, and support for complex relationships through foreign keys and joins.
- Limitations: Less suited for handling unstructured or semi-structured data or horizontal scaling.

### **2. NoSQL Databases**

“NoSQL” stands for “Not Only SQL” and includes databases designed to handle flexible data models.

**There are four types of NoSQL databases**:

- **Document-Oriented**Stores data in JSON-like documents. _Example: MongoDB, CouchDB._
- **Key-Value Stores**Simple and fast: each item is stored as a key and a value. _Example: Redis, DynamoDB._
- **Column-Family Stores (also known as wide column stores)** Organize data in columns instead of rows. _Example: Apache Cassandra, HBase._
- **Graph Databases**Focus on complex relationships and connections between data points. _Example: Neo4j, Amazon Neptune._

Ideal For: Social networks, recommendation engines, real-time analytics, IoT, and managing large volumes of sensor data from connected devices.

- Strengths: Scalability, flexibility, high performance with unstructured data.
- Limitations: Often no strict schema; may lack support for complex transactions.

_⚡ If your project involves flexible schemas or semi-structured data, a NoSQL database may be the way to go._

### **3. Object-Oriented Databases**

![[2.Types of Databases-1779628241138.webp]]

These databases store data as objects, similar to how programming languages like Java or Python define classes and objects.

- Structure: Objects contain both data and the methods to manipulate that data.
- Example Tools: db4o, ObjectDB.
- Ideal For: Applications built with object-oriented codebases; CAD, multimedia, simulations.
- Strengths: Seamless integration with OOP paradigms.
- Limitations: Less common in mainstream use; smaller ecosystem.

### **4. Hierarchical Databases**

One of the oldest database types, where data is stored in a tree-like structure.

- Structure: One parent node can have many child nodes, but each child only has one parent.
- Example Tools: IBM Information Management System (IMS).
- Ideal For: Legacy systems, file systems, org charts.
- Strengths: Fast for specific read operations with predictable paths.
- Limitations: Inflexible structure; poor support for many-to-many relationships.
