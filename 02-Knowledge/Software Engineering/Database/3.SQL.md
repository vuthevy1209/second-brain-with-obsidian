# SQL — Structured Query Language

> **SQL** is the standard language used to communicate with relational databases (MySQL, PostgreSQL, SQL Server…). It allows you to **create structures**, **manipulate data**, and **query** information.

SQL is divided into several sub-languages:

| Category | Purpose | Key Commands |
|---|---|---|
| **DDL** | Define database structure | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| **DML** | Manipulate data | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| **DCL** | Control access | `GRANT`, `REVOKE` |
| **TCL** | Manage transactions | `COMMIT`, `ROLLBACK` |

---

## 1. DDL — Data Definition Language

> DDL is used to **define and manage the structure** (schema) of a database — tables, columns, data types, constraints.

### CREATE TABLE

Creates a new table with columns and constraints.

```sql
CREATE TABLE employees (
    id         INT          PRIMARY KEY AUTO_INCREMENT,
    name       VARCHAR(100) NOT NULL,
    department VARCHAR(50),
    salary     DECIMAL(10, 2),
    hired_at   DATE
);
```

**Explanation:**
- `INT PRIMARY KEY AUTO_INCREMENT` → `id` is an integer, unique identifier, auto-increments (1, 2, 3…)
- `VARCHAR(100) NOT NULL` → `name` is a string up to 100 chars, cannot be empty
- `DECIMAL(10, 2)` → `salary` stores a number with up to 10 digits, 2 decimal places (e.g. `75000.50`)
- `DATE` → stores date in `YYYY-MM-DD` format

### ALTER TABLE

Modifies an existing table (add/remove/rename columns, change data types).

```sql
-- Add a new column
ALTER TABLE employees ADD COLUMN email VARCHAR(150);

-- Change column type
ALTER TABLE employees MODIFY COLUMN salary DECIMAL(12, 2);

-- Rename a column
ALTER TABLE employees RENAME COLUMN hired_at TO start_date;

-- Drop a column
ALTER TABLE employees DROP COLUMN email;
```

### DROP vs TRUNCATE

```sql
-- Remove the entire table (structure + data — PERMANENT!)
DROP TABLE employees;

-- Remove all rows but keep the table structure
TRUNCATE TABLE employees;
```

> [!WARNING]
> `DROP` deletes the table completely. `TRUNCATE` keeps the table shell but wipes all data. Both are **irreversible** without a backup.


### Common Constraints

| Constraint | Meaning |
|---|---|
| `PRIMARY KEY` | Uniquely identifies each row, cannot be NULL |
| `NOT NULL` | Column must have a value |
| `UNIQUE` | All values in column must be different |
| `DEFAULT` | Provides a default value if none is given |
| `FOREIGN KEY` | Links a column to a primary key in another table |
| `CHECK` | Enforces a condition on column values |

```sql
CREATE TABLE orders (
    order_id    INT          PRIMARY KEY AUTO_INCREMENT,
    customer_id INT          NOT NULL,
    amount      DECIMAL(10,2) CHECK (amount > 0),
    status      VARCHAR(20)  DEFAULT 'pending',
    FOREIGN KEY (customer_id) REFERENCES customers(id)
);
```

**Explanation:**
- `CHECK (amount > 0)` → MySQL will reject any insert where amount ≤ 0
- `DEFAULT 'pending'` → if `status` is not specified in INSERT, it automatically becomes `'pending'`
- `FOREIGN KEY (customer_id) REFERENCES customers(id)` → `customer_id` must match an existing `id` in the `customers` table

## 2. DML — Data Manipulation Language

> DML is used to **read and modify the actual data** inside tables.

### INSERT — Add new rows

```sql
-- Insert a single row
INSERT INTO employees (name, department, salary, hired_at)
VALUES ('Alice Nguyen', 'Engineering', 85000.00, '2023-06-15');

-- Insert multiple rows at once
INSERT INTO employees (name, department, salary, hired_at)
VALUES
    ('Bob Tran', 'Marketing', 62000.00, '2022-01-10'),
    ('Carol Le',  'Engineering', 91000.00, '2021-09-01'),
    ('David Pham', 'HR', 55000.00, '2024-03-20');
```

### SELECT — Query / Read data

```sql
-- Get all columns and all rows
SELECT * FROM employees;

-- Get specific columns
SELECT name, department, salary FROM employees;

-- With an alias (rename column in result)
SELECT name AS employee_name, salary AS monthly_salary
FROM employees;
```

**Explanation:** `AS` renames a column **only in the output** — it does not change the actual table.

### UPDATE — Modify existing rows

```sql
-- Give Alice a 10% raise
UPDATE employees
SET salary = salary * 1.10
WHERE name = 'Alice Nguyen';

-- Update multiple columns at once
UPDATE employees
SET department = 'Product', salary = 95000.00
WHERE name = 'Carol Le';
```

> [!CAUTION]
> **Always use `WHERE` with `UPDATE`!** Without it, every single row in the table gets modified.

### DELETE — Remove rows

```sql
-- Delete a specific row
DELETE FROM employees WHERE name = 'David Pham';

-- Delete all employees in a department
DELETE FROM employees WHERE department = 'HR';
```

> [!CAUTION]
> **Always use `WHERE` with `DELETE`!** `DELETE FROM employees;` (no WHERE) removes every row.

## 3. WHERE / GROUP BY / HAVING / ORDER BY

> These clauses **filter**, **group**, and **sort** query results.

### WHERE — Filter rows

```sql
-- Employees earning more than 70,000
SELECT name, salary FROM employees
WHERE salary > 70000;

-- Employees in Engineering hired after 2022
SELECT name, department, hired_at FROM employees
WHERE department = 'Engineering' AND hired_at > '2022-01-01';

-- Using IN, BETWEEN, LIKE
SELECT name FROM employees WHERE department IN ('Engineering', 'Product');
SELECT name, salary FROM employees WHERE salary BETWEEN 60000 AND 90000;
SELECT name FROM employees WHERE name LIKE 'A%';   -- starts with 'A'
SELECT name FROM employees WHERE name LIKE '%Nguyen'; -- ends with 'Nguyen'
```

**Explanation of operators:**

| Operator | Meaning | Example |
|---|---|---|
| `=` | Equals | `department = 'HR'` |
| `<>` or `!=` | Not equals | `status <> 'inactive'` |
| `>`, `<`, `>=`, `<=` | Comparisons | `salary >= 80000` |
| `IN (...)` | Matches any value in list | `id IN (1, 3, 5)` |
| `BETWEEN a AND b` | Within a range (inclusive) | `salary BETWEEN 50000 AND 100000` |
| `LIKE` | Pattern match (`%` = wildcard) | `name LIKE 'A%'` |
| `IS NULL` / `IS NOT NULL` | Check for NULL | `email IS NULL` |
| `AND`, `OR`, `NOT` | Combine conditions | `salary > 60000 AND dept = 'Eng'` |

### GROUP BY — Group rows

> `GROUP BY` collapses rows that share the same value into a single summary row. **Always used with aggregate functions.**

```sql
-- Count employees per department
SELECT department, COUNT(*) AS total_employees
FROM employees
GROUP BY department;
```

**Result:**

| department | total_employees |
|---|---|
| Engineering | 2 |
| Marketing | 1 |
| HR | 1 |

```sql
-- Average salary per department
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department;
```

### HAVING — Filter groups

> `HAVING` filters **after** `GROUP BY`. Use it instead of `WHERE` when filtering on aggregate results.

```sql
-- Only departments with more than 1 employee
SELECT department, COUNT(*) AS total
FROM employees
GROUP BY department
HAVING COUNT(*) > 1;

-- Departments where average salary > 75,000
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 75000;
```

> [!NOTE]
> **`WHERE` vs `HAVING`:**
> - `WHERE` filters **individual rows** → applied **before** grouping
> - `HAVING` filters **groups** → applied **after** grouping
>
> ```sql
> -- WHERE: filter rows first, then group
> SELECT department, COUNT(*) FROM employees
> WHERE salary > 60000          -- ← filters rows first
> GROUP BY department
> HAVING COUNT(*) > 1;          -- ← then filters groups
> ```

### ORDER BY — Sort results

```sql
-- Sort by salary descending (highest first)
SELECT name, salary FROM employees
ORDER BY salary DESC;

-- Sort by department alphabetically, then salary descending
SELECT name, department, salary FROM employees
ORDER BY department ASC, salary DESC;
```

### LIMIT — Restrict result count

```sql
-- Get top 3 highest-paid employees
SELECT name, salary FROM employees
ORDER BY salary DESC
LIMIT 3;

-- Pagination: skip first 10 rows, get next 5
SELECT name, salary FROM employees
ORDER BY salary DESC
LIMIT 5 OFFSET 10;
```

## 4. Aggregate Functions

> Aggregate functions **compute a single result from a set of rows**.

| Function | Returns |
|---|---|
| `COUNT(*)` | Number of rows |
| `COUNT(col)` | Number of non-NULL values in a column |
| `SUM(col)` | Total sum of values |
| `AVG(col)` | Average of values |
| `MAX(col)` | Maximum value |
| `MIN(col)` | Minimum value |

```sql
-- Total number of employees
SELECT COUNT(*) AS total_employees FROM employees;

-- Total salary expense
SELECT SUM(salary) AS total_payroll FROM employees;

-- Average salary
SELECT AVG(salary) AS avg_salary FROM employees;

-- Highest and lowest salary
SELECT MAX(salary) AS highest, MIN(salary) AS lowest FROM employees;
```

**Combining aggregates with GROUP BY:**

```sql
SELECT
    department,
    COUNT(*)        AS headcount,
    SUM(salary)     AS total_cost,
    AVG(salary)     AS avg_salary,
    MAX(salary)     AS top_earner,
    MIN(salary)     AS entry_salary
FROM employees
GROUP BY department;
```

**Result:**

| department | headcount | total_cost | avg_salary | top_earner | entry_salary |
|---|---|---|---|---|---|
| Engineering | 2 | 176000 | 88000 | 91000 | 85000 |
| Marketing | 1 | 62000 | 62000 | 62000 | 62000 |

> [!NOTE]
> `COUNT(*)` counts all rows including NULLs. `COUNT(salary)` counts only rows where `salary` is not NULL.

## 5. JOIN — Combining Tables

> `JOIN` merges rows from two or more tables based on a **related column** (usually a foreign key).

### Setup for examples

```sql
CREATE TABLE departments (
    dept_id   INT PRIMARY KEY,
    dept_name VARCHAR(50)
);

INSERT INTO departments VALUES (1, 'Engineering'), (2, 'Marketing'), (3, 'HR'), (4, 'Finance');

-- Assume employees table has a dept_id column
ALTER TABLE employees ADD COLUMN dept_id INT;
UPDATE employees SET dept_id = 1 WHERE department = 'Engineering';
UPDATE employees SET dept_id = 2 WHERE department = 'Marketing';
-- Note: some employees may have no dept_id (NULL)
```

### INNER JOIN — Only matching rows

> Returns rows where the condition matches **in both tables**. Rows with no match are excluded.

```sql
SELECT e.name, e.salary, d.dept_name
FROM employees e
INNER JOIN departments d ON e.dept_id = d.dept_id;
```

**Explanation:**
- `employees e` → alias `e` for shorter reference
- `INNER JOIN departments d` → join with departments table (alias `d`)
- `ON e.dept_id = d.dept_id` → match condition: link employee's dept_id to department's dept_id
- Only employees **with a valid dept_id** that exists in `departments` are returned

### LEFT JOIN — All left table rows + matches from right

> Returns **all rows from the left table**, and the matched rows from the right table. If no match, right side columns are `NULL`.

```sql
SELECT e.name, d.dept_name
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.dept_id;
```

**Result:** Employees with no department assignment still appear, but `dept_name` will be `NULL`.

| name | dept_name |
|---|---|
| Alice Nguyen | Engineering |
| Bob Tran | Marketing |
| Carol Le | Engineering |
| David Pham | NULL |

### RIGHT JOIN — All right table rows + matches from left

> Returns **all rows from the right table**, plus matching rows from the left. If no match, left side is `NULL`.

```sql
SELECT e.name, d.dept_name
FROM employees e
RIGHT JOIN departments d ON e.dept_id = d.dept_id;
```

**Result:** All departments appear even if no employee belongs to them.

| name | dept_name |
|---|---|
| Alice Nguyen | Engineering |
| Bob Tran | Marketing |
| Carol Le | Engineering |
| NULL | HR |
| NULL | Finance |

### FULL OUTER JOIN

> Returns **all rows from both tables**. Where there's no match, NULL fills the gap.

> [!NOTE]
> MySQL does **not** support `FULL OUTER JOIN` directly. Simulate it with `UNION`:
> ```sql
> SELECT e.name, d.dept_name
> FROM employees e LEFT JOIN departments d ON e.dept_id = d.dept_id
> UNION
> SELECT e.name, d.dept_name
> FROM employees e RIGHT JOIN departments d ON e.dept_id = d.dept_id;
> ```

### Self JOIN — Join a table with itself

> Useful when rows in a table reference other rows in the **same table** (e.g., manager-employee hierarchy).

```sql
-- Assume employees has a manager_id column that references employees.id
SELECT
    e.name        AS employee,
    m.name        AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
```

### JOIN Summary

```
Table A    Table B
  ┌────┐    ┌────┐
  │  ██│████│██  │   INNER JOIN  → only the overlap (██)
  │    │████│    │   LEFT JOIN   → all of A + overlap
  │    │████│    │   RIGHT JOIN  → overlap + all of B
  └────┘    └────┘   FULL OUTER  → everything
```

## 6. Subquery

> A **subquery** (or nested query) is a `SELECT` statement **inside** another SQL statement. It can appear in `WHERE`, `FROM`, or `SELECT` clauses.

### Subquery in WHERE

```sql
-- Find employees earning more than the company average
SELECT name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
```

**Explanation:**
1. The inner query `(SELECT AVG(salary) FROM employees)` runs first → returns a single value, e.g. `73250`
2. The outer query then runs: `WHERE salary > 73250`
3. Result: only employees above average are returned

```sql
-- Find employees in the 'Engineering' department (using subquery instead of JOIN)
SELECT name FROM employees
WHERE dept_id = (SELECT dept_id FROM departments WHERE dept_name = 'Engineering');
```

### Subquery with IN

```sql
-- Find employees in departments located in 'Hanoi'
-- Assume departments has a city column
SELECT name FROM employees
WHERE dept_id IN (
    SELECT dept_id FROM departments WHERE city = 'Hanoi'
);
```

**Explanation:** The subquery returns a **list** of dept_ids. The outer query returns employees whose dept_id is in that list.

### Subquery in FROM (Derived Table)

```sql
-- Get departments where the average salary > 80,000
SELECT dept_summary.department, dept_summary.avg_salary
FROM (
    SELECT department, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department
) AS dept_summary
WHERE dept_summary.avg_salary > 80000;
```

**Explanation:**
- The inner `SELECT` creates a temporary table `dept_summary` with two columns
- The outer query filters that temporary table just like a normal table
- The `AS dept_summary` alias is **required** in MySQL when using a derived table

### Subquery in SELECT (Scalar Subquery)

```sql
-- Show each employee's salary compared to the overall average
SELECT
    name,
    salary,
    (SELECT AVG(salary) FROM employees) AS company_avg,
    salary - (SELECT AVG(salary) FROM employees) AS diff_from_avg
FROM employees;
```

**Explanation:** The subquery in `SELECT` returns one value and is computed for **every row**.

### EXISTS / NOT EXISTS

```sql
-- Find departments that have at least one employee
SELECT dept_name FROM departments d
WHERE EXISTS (
    SELECT 1 FROM employees e WHERE e.dept_id = d.dept_id
);

-- Find departments with no employees
SELECT dept_name FROM departments d
WHERE NOT EXISTS (
    SELECT 1 FROM employees e WHERE e.dept_id = d.dept_id
);
```

**Explanation:**
- `EXISTS` returns `TRUE` if the subquery returns **any rows**
- `SELECT 1` is used as a convention — we only care whether rows exist, not what they contain
- This is a **correlated subquery** — the inner query references `d.dept_id` from the outer query, so it re-evaluates for each row in `departments`

### Subquery vs JOIN — When to use which?

| Use case | Prefer |
|---|---|
| Simple filtering using another table's data | `JOIN` (usually faster) |
| The subquery returns a single value | Subquery in `WHERE` |
| Checking existence/absence | `EXISTS` / `NOT EXISTS` |
| Complex intermediate aggregation | Subquery in `FROM` |

## Full Query Execution Order

Understanding the **logical order** MySQL processes a query prevents common confusion:

```sql
SELECT   department, AVG(salary) AS avg_sal   -- 6. Select columns
FROM     employees                             -- 1. Get the table
JOIN     departments ON ...                    -- 2. Join tables
WHERE    hired_at > '2021-01-01'               -- 3. Filter rows
GROUP BY department                            -- 4. Group rows
HAVING   AVG(salary) > 70000                  -- 5. Filter groups
ORDER BY avg_sal DESC                          -- 7. Sort results
LIMIT    5;                                    -- 8. Limit output
```

> [!NOTE]
> This is **logical** order (how SQL thinks), not the order you write clauses. You must write them in: `SELECT → FROM → JOIN → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`.

## Quick Reference

```sql
-- DDL
CREATE TABLE t (id INT PRIMARY KEY, name VARCHAR(50));
ALTER TABLE t ADD COLUMN age INT;
DROP TABLE t;
TRUNCATE TABLE t;

-- DML
INSERT INTO t (name, age) VALUES ('Alice', 25);
SELECT * FROM t WHERE age > 20 ORDER BY name LIMIT 10;
UPDATE t SET age = 26 WHERE name = 'Alice';
DELETE FROM t WHERE name = 'Alice';

-- Aggregate
SELECT COUNT(*), SUM(age), AVG(age), MAX(age), MIN(age) FROM t;

-- GROUP BY + HAVING
SELECT name, COUNT(*) FROM t GROUP BY name HAVING COUNT(*) > 1;

-- JOIN
SELECT a.col, b.col FROM a INNER JOIN b ON a.id = b.a_id;
SELECT a.col, b.col FROM a LEFT  JOIN b ON a.id = b.a_id;

-- Subquery
SELECT * FROM t WHERE age > (SELECT AVG(age) FROM t);
SELECT * FROM t WHERE id IN (SELECT id FROM other_table WHERE ...);
```

# Quiz

> [!question] Bạn cần xóa toàn bộ dữ liệu trong bảng `logs` nhưng vẫn giữ nguyên cấu trúc bảng. Lệnh nào phù hợp?
> a) `DROP TABLE logs;`
> b) `DELETE TABLE logs;`
> c) `TRUNCATE TABLE logs;`
> d) `ALTER TABLE logs DELETE ALL;`
>> [!success]- Answer
>> c) `TRUNCATE TABLE logs;`
>>
>> `TRUNCATE` xóa toàn bộ dữ liệu nhưng giữ lại cấu trúc bảng (columns, constraints). `DROP` xóa luôn cả bảng.

> [!question] Câu lệnh sau có vấn đề gì? `UPDATE employees SET salary = 100000;`
> a) Cú pháp sai, thiếu `FROM`
> b) Cú pháp đúng nhưng sẽ cập nhật **tất cả** nhân viên thành 100000
> c) Lỗi vì không có `WHERE PRIMARY KEY`
> d) Không có vấn đề gì cả
>> [!success]- Answer
>> b) Cú pháp đúng nhưng sẽ cập nhật **tất cả** nhân viên thành 100000
>>
>> Thiếu mệnh đề `WHERE` khiến UPDATE áp dụng lên mọi row trong bảng — đây là một lỗi rất nguy hiểm trong thực tế.

> [!question] Sự khác biệt chính giữa `WHERE` và `HAVING` là gì?
> a) `WHERE` dùng cho chuỗi, `HAVING` dùng cho số
> b) `WHERE` lọc trước khi nhóm, `HAVING` lọc sau khi nhóm
> c) `WHERE` chỉ dùng với `SELECT`, `HAVING` dùng với mọi lệnh DML
> d) Không có sự khác biệt — chúng có thể hoán đổi cho nhau
>> [!success]- Answer
>> b) `WHERE` lọc trước khi nhóm, `HAVING` lọc sau khi nhóm
>>
>> `WHERE` lọc từng row trước `GROUP BY`. `HAVING` lọc các nhóm đã được tổng hợp, nên có thể dùng aggregate functions như `COUNT(*)`, `AVG()`.

> [!question] `INNER JOIN` trả về kết quả như thế nào?
> a) Tất cả rows từ bảng trái, kể cả khi không có match ở bảng phải
> b) Tất cả rows từ cả hai bảng dù có match hay không
> c) Chỉ những rows có giá trị khớp nhau ở **cả hai bảng**
> d) Tất cả rows từ bảng phải, kể cả khi không match ở bảng trái
>> [!success]- Answer
>> c) Chỉ những rows có giá trị khớp nhau ở **cả hai bảng**
>>
>> `INNER JOIN` loại bỏ mọi row không tìm được cặp khớp. Dùng `LEFT JOIN` nếu bạn cần giữ lại tất cả rows từ bảng trái.

> [!question] Truy vấn sau trả về gì? `SELECT name FROM employees WHERE salary > (SELECT AVG(salary) FROM employees);`
> a) Nhân viên có lương thấp hơn trung bình
> b) Nhân viên có lương bằng đúng trung bình
> c) Nhân viên có lương **cao hơn** mức lương trung bình toàn công ty
> d) Lỗi vì không thể dùng subquery trong WHERE
>> [!success]- Answer
>> c) Nhân viên có lương **cao hơn** mức lương trung bình toàn công ty
>>
>> Subquery `(SELECT AVG(salary) FROM employees)` chạy trước và trả về một giá trị số (vd: 73250). Query ngoài sau đó lọc các nhân viên có salary lớn hơn giá trị đó.

> [!question] Khi nào nên dùng `EXISTS` thay vì `IN`?
> a) Khi subquery trả về một giá trị duy nhất
> b) Khi muốn kiểm tra **sự tồn tại** của rows trong subquery, đặc biệt khi subquery có thể trả về nhiều rows và hiệu suất quan trọng
> c) `EXISTS` và `IN` hoàn toàn giống nhau, chọn cái nào cũng được
> d) Khi cần sort kết quả của subquery
>> [!success]- Answer
>> b) Khi muốn kiểm tra **sự tồn tại** của rows trong subquery, đặc biệt khi subquery có thể trả về nhiều rows và hiệu suất quan trọng
>>
>> `EXISTS` dừng lại ngay khi tìm được row đầu tiên khớp (short-circuit), trong khi `IN` phải thu thập toàn bộ kết quả của subquery trước. `EXISTS` thường hiệu quả hơn với correlated subqueries và tập dữ liệu lớn.

> [!question] Thứ tự thực thi logic của SQL là gì?
> a) SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
> b) FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
> c) WHERE → FROM → SELECT → GROUP BY → ORDER BY
> d) SELECT → WHERE → FROM → HAVING → GROUP BY
>> [!success]- Answer
>> b) FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
>>
>> SQL xử lý FROM/JOIN đầu tiên để lấy dữ liệu nguồn, rồi WHERE lọc rows, GROUP BY nhóm, HAVING lọc nhóm, SELECT chọn columns, ORDER BY sắp xếp, LIMIT cắt kết quả. Đây là lý do bạn không thể dùng alias từ SELECT trong WHERE.
