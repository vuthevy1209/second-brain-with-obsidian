## Execution Order

```
┌─────────────────────────────────────────────────────────────┐
│  Step │ Clause       │ What happens                         │
│──────────────────────────────────────────────────────────── │
│   1   │ FROM         │ Load table(s) into memory            │
│   2   │ JOIN         │ Merge tables using join condition    │
│   3   │ WHERE        │ Filter individual rows               │
│   4   │ GROUP BY     │ Group remaining rows                 │
│   5   │ HAVING       │ Filter groups                        │
│   6   │ SELECT       │ Pick which columns to output         │
│   7   │ ORDER BY     │ Sort the result set                  │
│   8   │ LIMIT/OFFSET │ Cut output to specified number       │
└─────────────────────────────────────────────────────────────┘
```

> [!IMPORTANT]
> Because `SELECT` runs at step 6, you **cannot** use column aliases defined in `SELECT` inside `WHERE` or `HAVING` — those clauses run before `SELECT` sees the aliases.

## Example

```sql
SELECT   MABM, AVG(LUONG) AS LUONG_TB   -- 6. pick columns + alias
FROM     GIAOVIEN                        -- 1. load table
JOIN     BOMON ON GIAOVIEN.MABM = BOMON.MABM  -- 2. merge
WHERE    PHAI = 'Nữ'                     -- 3. filter rows
GROUP BY MABM                            -- 4. group
HAVING   AVG(LUONG) > 15000000           -- 5. filter groups (use AVG, NOT alias)
ORDER BY LUONG_TB DESC                   -- 7. sort (alias OK here)
LIMIT    5;                              -- 8. cut output
```

> [!NOTE]
> `ORDER BY` is the **only** clause that can reference a `SELECT` alias, because it executes after `SELECT`.
