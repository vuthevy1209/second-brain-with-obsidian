### 1. Tổng quan về Vòng đời Servlet (Servlet Lifecycle)

> [!NOTE] Tóm tắt nhanh
> - Toàn bộ vòng đời của Servlet do **Servlet Container (như Apache Tomcat)** kiểm soát và quản lý từ đầu đến cuối.
> - Servlet hoạt động theo kiến trúc **Single Instance - Multi-threaded** (Chỉ tạo **1 đối tượng duy nhất** cho mỗi Servlet class, nhưng phục vụ **nhiều Request đồng thời** bằng các Thread riêng biệt).

![[03. Vòng đời servlet-1786181439030.webp]]

Vòng đời của Servlet bao gồm 4 giai đoạn chính:
- `init()` → Gọi **1 lần duy nhất** khi Servlet được nạp và khởi tạo.
- `service()` → Gọi **mỗi khi có request** gửi tới.
- `doGet()` / `doPost()` → Được `service()` điều hướng để xử lý theo HTTP method tương ứng.
- `destroy()` → Gọi **1 lần duy nhất** trước khi Servlet bị hủy bỏ và giải phóng.

### 2. Chi tiết các giai đoạn trong Vòng đời Servlet

```
                [Client gửi Request]
                         │
                         ▼
        ┌──────────────────────────────────┐
        │  1. Nạp Class & Tạo Instance     │  (Gọi Constructor không tham số)
        └────────────────┬─────────────────┘
                         │
                         ▼
        ┌──────────────────────────────────┐
        │  2. Khởi tạo: init()             │  (Chỉ chạy 1 LẦN DUY NHẤT)
        └────────────────┬─────────────────┘
                         │
                         ▼
        ┌──────────────────────────────────┐
   ┌───►│  3. Xử lý Request: service()     │  (Chạy MỖI REQUEST, đa luồng)
   │    │     └── doGet() / doPost()       │
   │    └────────────────┬─────────────────┘
   └────────── lặp lại ──┘ (khi có request mới)
                         │
                         ▼ (Khi Server tắt / Reload App)
        ┌──────────────────────────────────┐
        │  4. Hủy Servlet: destroy()       │  (Chỉ chạy 1 LẦN DUY NHẤT)
        └────────────────┬─────────────────┘
                         │
                         ▼
        ┌──────────────────────────────────┐
        │  5. Thu gom rác (JVM GC)         │
        └──────────────────────────────────┘
```

#### Giai đoạn 1: Nạp Class và Tạo Instance (Loading & Instantiation)
- **Cơ chế:** Khi có request đầu tiên khớp với URL mapping của Servlet, Servlet Container dùng `ClassLoader` nạp file `.class` vào bộ nhớ và gọi **Constructor mặc định (no-arg constructor)** để tạo đối tượng.
- **Thời điểm khởi tạo:**
  - **Mặc định (Lazy Loading):** Servlet chỉ được tạo khi có request đầu tiên gửi đến.
  - **Khởi động cùng Server (Eager Loading):** Nếu cấu hình `@WebServlet(value = "/hello", loadOnStartup = 1)` (với giá trị $\ge 0$), Container sẽ tạo instance ngay khi Tomcat vừa start.
- **Tính chất:** <mark style="background:#affad1">Container chỉ duy trì **1 Instance duy nhất** của mỗi Servlet class trong suốt thời gian chạy</mark>.

#### Giai đoạn 2: Khởi tạo (Initialization - `init()`)
- **Cơ chế:** Ngay sau khi instance được tạo, Container sẽ gọi phương thức `init(ServletConfig config)` (hoặc `init()`).
- **Tần suất:** <mark style="background:#d3f8b6">Chỉ được gọi **1 lần duy nhất** trong toàn bộ vòng đời của Servlet</mark>.
- **Mục đích sử dụng:**
  - Đọc các tham số cấu hình khởi tạo (`init-param`).
  - Mở kết nối Database Pool, nạp dữ liệu cấu hình vào bộ nhớ đệm (Cache), thiết lập tài nguyên dùng chung.

#### Giai đoạn 3: Xử lý Request (Request Handling - `service()`)
- **Cơ chế:** Mỗi khi Client gửi Request đến URL của Servlet:
  1. Container lấy/tạo một **Thread mới** từ Thread Pool để xử lý riêng biệt.
  2. Tạo 2 đối tượng:
     - `HttpServletRequest`: Chứa toàn bộ thông tin từ Client (Headers, Parameters, Cookies, Body,...).
     - `HttpServletResponse`: Đối tượng để ghi dữ liệu trả về cho Client (HTML, JSON, Redirect, Headers,...).
  3. Container gọi hàm `service(request, response)`.
  4. Hàm `service()` mặc định của `HttpServlet` sẽ phân tích HTTP Method (GET, POST, PUT, DELETE,...) và tự động gọi hàm tương ứng (`doGet`, `doPost`, `doPut`, `doDelete`,...).
- **Tần suất:** Gọi **mỗi lần** có request đến.

#### Giai đoạn 4: Hủy Servlet (Destruction - `destroy()`)
- **Thời điểm gọi:** 
  - Khi Web Server / Tomcat bị **Shutdown**.
  - Khi ứng dụng web bị **Undeploy** hoặc **Reload** (Hot deploy).
- **Tần suất:** Gọi **1 lần duy nhất** trước khi Servlet instance bị giải phóng hoàn toàn.
- **Mục đích sử dụng:**
  - Đóng kết nối Database, đóng file streams, ngắt kết nối mạng socket, dừng các Background Threads để tránh **Memory Leak**.

#### Giai đoạn 5: Garbage Collection (Thu gom rác)
- Sau khi `destroy()` chạy xong, Servlet instance không còn tham chiếu nào và sẽ được bộ thu gom rác (Garbage Collector) của JVM dọn dẹp bộ nhớ RAM.

### 3. Code minh họa Vòng đời Servlet

```java
package org.example.servlet;

import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import java.io.IOException;

@WebServlet("/hello")
public class HelloServlet extends HttpServlet {

    // 1. Chạy 1 lần duy nhất khi Servlet được tạo
    @Override
    public void init() throws ServletException {
        super.init();
        System.out.println(">>> [HelloServlet] init() được gọi - Servlet đã được khởi tạo và sẵn sàng nhận request!");
    }

    // 2. Chạy mỗi khi có HTTP GET request gửi đến
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {

        System.out.println(">>> [HelloServlet] doGet() được gọi - Đang xử lý request trên Thread: " 
                + Thread.currentThread().getName());

        req.setAttribute("message", "Hello từ Servlet!");

        req.getRequestDispatcher("/hello.jsp")
                .forward(req, resp);
    }

    // 3. Chạy 1 lần duy nhất khi Server tắt hoặc Reload app
    @Override
    public void destroy() {
        System.out.println(">>> [HelloServlet] destroy() được gọi - Servlet sắp bị hủy giải phóng tài nguyên!");
        super.destroy();
    }
}
```

### 4. Bảng tổng kết các hàm Vòng đời

| Phương thức | Tần suất gọi | Thời điểm gọi | Nhiệm vụ chính |
| :--- | :--- | :--- | :--- |
| `init()` | **1 lần** | Sau khi instance được tạo | Khởi tạo tài nguyên dùng chung, kết nối DB, đọc config |
| `service()` | **Mỗi request** | Khi có request từ client gửi đến | Điều hướng sang `doGet`, `doPost`, `doPut`,... |
| `doGet()` / `doPost()` | **Mỗi request** | Được gọi bởi `service()` | Thực hiện logic xử lý nghiệp vụ theo từng HTTP Method |
| `destroy()` | **1 lần** | Khi Server dừng hoặc reload | Đóng tài nguyên, dọn dẹp bộ nhớ, ngắt kết nối |

### 5. Lưu ý quan trọng & Câu hỏi phỏng vấn (Interview Tips)

> [!QUESTION] Nếu project có 2 Servlet (`HelloServlet` và `TestServlet`), chúng có dùng chung 1 instance không?
> - **KHÔNG!** Mỗi **Servlet Class riêng biệt** sẽ có **1 Instance riêng biệt** trong bộ nhớ của Servlet Container (Tomcat).
> - **Giải thích chi tiết:**
>   - Khái niệm **Single Instance** có nghĩa là: *Mỗi Servlet Class / mỗi URL mapping duy trì duy nhất 1 đối tượng*. Không phải toàn bộ ứng dụng web chỉ có 1 instance dùng chung.
>   - Khi bạn truy cập `/hello` lần đầu $\rightarrow$ Tomcat tạo instance của `HelloServlet` $\rightarrow$ gọi `init()` của `HelloServlet` (lần 1).
>   - Khi bạn truy cập `/test` lần đầu $\rightarrow$ Tomcat tạo instance của `TestServlet` $\rightarrow$ gọi `init()` của `TestServlet` (lần 2).
>   - Khi truy cập lại `/hello` hay `/test` các lần tiếp theo (F5 nhiều lần) $\rightarrow$ Tomcat **tái sử dụng instance cũ** $\rightarrow$ **KHÔNG gọi lại `init()` nữa**, mà chỉ gọi `doGet()`/`doPost()`.

```
                  ┌────────────────────────────────────────────────┐
                  │                 BỘ NHỚ TOMCAT                  │
                  │                                                │
/hello (Request) ─┼──► Instance của HelloServlet (Chỉ có 1 cái)    │
                  │      └── init() được gọi 1 lần khi tạo         │
                  │                                                │
/test  (Request) ─┼──► Instance của TestServlet  (Chỉ có 1 cái)    │
                  │      └── init() được gọi 1 lần khi tạo         │
                  └────────────────────────────────────────────────┘
```

> [!IMPORTANT] Servlet có Thread-safe (an toàn đa luồng) không?
> - **KHÔNG!** Vì mỗi Servlet chỉ có **1 instance duy nhất** nhưng được gọi bởi **nhiều thread cùng lúc** (Multi-threading).
> - **Quy tắc an toàn:**
>   - ❌ **KHÔNG** khai báo biến trạng thái (stateful variables) hay dữ liệu riêng của người dùng ở cấp độ **Instance Variable (biến toàn cục của class)**.
>   - ✅ **NÊN** khai báo biến bên trong các phương thức (`doGet`, `doPost` - biến cục bộ `local variables`), vì biến cục bộ được lưu trên Stack riêng của từng Thread nên hoàn toàn an toàn đa luồng (Thread-safe).

### 6. Mở rộng: Phân biệt Servlet thuần (HttpServlet) vs DispatcherServlet (Spring MVC)

#### 6.1. Vấn đề của Servlet thuần (Multi-Servlet Pattern)
- Trong mô hình Servlet thuần, mỗi chức năng hoặc URL mapping thường cần một Servlet class riêng biệt (`HelloServlet`, `UserServlet`, `ProductServlet`,...).
- **Nhược điểm:** Dễ trùng lặp code xử lý chung (như filter kiểm tra xác thực, bắt lỗi exception, parse request, format dữ liệu trả về,...).

```
[Mô hình Servlet truyền thống]

Client Request: /hello   ──────► HelloServlet   ───► hello.jsp
Client Request: /user    ──────► UserServlet    ───► user.jsp
Client Request: /product ──────► ProductServlet ───► product.jsp
```

#### 6.2. DispatcherServlet là gì? (Front Controller Pattern)
- **Định nghĩa:** `DispatcherServlet` là một Servlet đặc biệt đóng vai trò là **Front Controller (Cửa ngõ duy nhất)** tiếp nhận **toàn bộ request** gửi đến ứng dụng (thường map với URL pattern `/`).
- **Bản chất:** `DispatcherServlet` vẫn kế thừa từ `HttpServlet` (vẫn có đủ vòng đời `init()`, `service()`, `destroy()`), nhưng thay vì tự xử lý logic, nó đóng vai trò **điều phối (dispatch)** request tới các Controller tương ứng.

```
[Mô hình Front Controller với DispatcherServlet (Spring MVC)]

Client Request: /hello   ──┐
Client Request: /user    ──┼──► [ DispatcherServlet ] ──► Điều phối tới:
Client Request: /product ──┘    (Front Controller)         ├── HelloController
                                                           ├── UserController
                                                           └── ProductController
```

#### 6.3. Luồng xử lý của DispatcherServlet

```
                  ┌────────────────────────┐
                  │         Client         │
                  └───────────┬────────────┘
                              │ 1. Gửi Request (VD: GET /users)
                              ▼
               ┌──────────────────────────────┐
               │      DispatcherServlet       │ ◄── [Cửa ngõ chính]
               └──────┬────────────────┬──────┘
       2. Tìm Controller               │ 3. Ủy quyền xử lý
              ▼                        ▼
     ┌─────────────────┐      ┌─────────────────┐
     │ HandlerMapping  │      │   Controller    │ (Xử lý nghiệp vụ)
     └─────────────────┘      └────────┬────────┘
                                       │ 4. Trả về Model / View / JSON
                                       ▼
                              ┌─────────────────┐
                              │  ViewResolver   │ (Render JSP/HTML hoặc JSON)
                              └────────┬────────┘
                                       │ 5. Trả Response
                                       ▼
                  ┌────────────────────────┐
                  │         Client         │
                  └────────────────────────┘
```

1. **Nhận Request:** `DispatcherServlet` tiếp nhận request từ Client.
2. **Tìm Controller (`HandlerMapping`):** Tra cứu xem URL này khớp với Controller / Method nào (ví dụ `@GetMapping("/users")`).
3. **Thực thi (`HandlerAdapter` & `Controller`):** Gọi Controller tương ứng để xử lý nghiệp vụ, truy vấn Database.
4. **Xử lý kết quả:** Controller trả về kết quả (View Name hoặc Dữ liệu Object/JSON).
5. **Trả Response (`ViewResolver` / MessageConverter):** Chuyển đổi dữ liệu thành HTML hoặc JSON để gửi về cho Client.

#### 6.4. Bảng so sánh tổng quan

| Tiêu chí | Servlet thuần (`HttpServlet`) | DispatcherServlet (Spring MVC) |
| :--- | :--- | :--- |
| **Mẫu thiết kế** | Multi-Servlet Pattern | **Front Controller Pattern** |
| **Số lượng Servlet** | Nhiều Servlet độc lập (`HelloServlet`, `TestServlet`,...) | **Duy nhất 1 Servlet** (`DispatcherServlet`) quản lý toàn app |
| **Cấu hình URL Mapping** | Mỗi Servlet có `@WebServlet("/path")` riêng | `DispatcherServlet` map vào `/` hoặc `/*`, các Controller dùng `@RequestMapping` |
| **Vai trò Controller** | Servlet vừa quản lý kết nối HTTP vừa xử lý logic | Controller chỉ là các Java Class thông thường (POJO) với `@Controller` / `@RestController` |
| **Xử lý dùng chung** | Phải viết nhiều `Filter` hoặc lặp lại code trong từng Servlet | Tập trung tại `DispatcherServlet`, `Interceptor`, và `Filter` |
| **Tính ứng dụng** | Học để hiểu nền tảng giao tiếp HTTP & Container | Là tiêu chuẩn công nghiệp khi phát triển Web App / REST API với Spring Boot |
