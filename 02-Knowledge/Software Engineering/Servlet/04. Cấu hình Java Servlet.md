### 1. Tổng quan về các cách cấu hình Java Servlet

Trong ứng dụng Java Web, <mark style="background:#d3f8b6">để Servlet Container (như **Tomcat**) biết được</mark>:
1. Servlet class nào đang tồn tại trong hệ thống.
2. Đường dẫn URL nào sẽ được ánh xạ (map) đến Servlet đó để xử lý request.

Chúng ta có <mark style="background:#affad1"><font color="#000000">**2 cách cấu hình chính**:</font></mark>
- **Cách 1 (Truyền thống):** Cấu hình qua file triển khai `web.xml` (Deployment Descriptor - Chuẩn từ **Servlet 2.x** trở về trước).
- **Cách 2 (Hiện đại):** Cấu hình qua Annotation `@WebServlet` (Xuất hiện từ **Servlet 3.0** trở đi).

---

### 2. Cấu hình Servlet bằng XML (`web.xml`)

File `web.xml` còn được gọi là **Deployment Descriptor (Bộ mô tả triển khai)**, luôn nằm tại thư mục bắt buộc: `src/main/webapp/WEB-INF/web.xml`.

#### 2.1. Cặp thẻ cốt lõi trong `web.xml`

Để cấu hình một Servlet, ta cần định nghĩa **2 khối thẻ bắt buộc**:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee
         https://jakarta.ee/xml/ns/jakartaee/web-app_6_0.xsd"
         version="6.0">

    <!-- 1. ĐĂNG KÝ SERVLET VỚI CONTAINER -->
    <servlet>
        <servlet-name>configXmlServlet</servlet-name>
        <servlet-class>org.example.servlet.ConfigXmlServlet</servlet-class>
    </servlet>

    <!-- 2. ÁNH XẠ ĐƯỜNG DẪN URL TỚI SERVLET -->
    <servlet-mapping>
        <servlet-name>configXmlServlet</servlet-name>
        <url-pattern>/config-xml</url-pattern>
    </servlet-mapping>

</web-app>
```

> [!TIP] Nguyên lý liên kết
> Thẻ `<servlet-name>` đóng vai trò là **chiếc cầu nối** liên kết giữa phần khai báo class (`<servlet>`) và phần định tuyến URL (`<servlet-mapping>`). Giá trị `<servlet-name>` ở 2 khối thẻ này **bắt buộc phải giống hệt nhau**.

#### 2.2. Chi tiết các thẻ con thường gặp trong `<servlet>`:

- `<servlet-name>`: Tên định danh nội bộ của Servlet trong ứng dụng (tự đặt, không được trùng lặp).
- `<servlet-class>`: Đường dẫn đầy đủ của class Java (Fully Qualified Class Name bao gồm cả package, ví dụ `org.example.servlet.ConfigXmlServlet`).
- `<load-on-startup>`: *(Tùy chọn)* Số nguyên xác định thứ tự khởi tạo khi Tomcat khởi động:
  - Nếu $\ge 0$: Servlet được tạo và chạy `init()` ngay khi Server bật (Eager Loading).
  - Nếu $< 0$ hoặc không khai báo: Servlet chỉ được tạo khi có request đầu tiên (Lazy Loading).
- `<init-param>`: *(Tùy chọn)* Tham số khởi tạo dùng riêng cho Servlet đó (được đọc qua `getServletConfig().getInitParameter("key")`).

#### 2.3. Mã nguồn Java khi cấu hình bằng XML ([ConfigXmlServlet.java](file:///Users/vuthevy1209/Documents/Project/learn-servlet/src/main/java/org/example/servlet/ConfigXmlServlet.java))

Khi dùng XML, class Java **hoàn toàn là POJO kế thừa `HttpServlet`** và **KHÔNG** cần gắn bất kỳ annotation nào:

```java
package org.example.servlet;

import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.io.PrintWriter;

public class ConfigXmlServlet extends HttpServlet {

    @Override
    public void init() throws ServletException {
        super.init();
        System.out.println(">>> [ConfigXmlServlet] init() được gọi qua cấu hình web.xml!");
    }

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {

        resp.setContentType("text/html;charset=UTF-8");
        try (PrintWriter out = resp.getWriter()) {
            out.println("<h1>Chào bạn! Servlet này được cấu hình bằng web.xml</h1>");
            out.println("<p>URL Mapping: <code>/config-xml</code></p>");
        }
    }

    @Override
    public void destroy() {
        System.out.println(">>> [ConfigXmlServlet] destroy() được gọi!");
        super.destroy();
    }
}
```

### 3. Cấu hình Servlet bằng Annotation (`@WebServlet`)

Từ **Servlet 3.0 (Java EE 6)** trở đi, Java giới thiệu cơ chế cấu hình trực tiếp qua **Annotation** để đơn giản hóa quá trình phát triển và loại bỏ sự phụ thuộc vào file `web.xml`.

#### 3.1. Các cách viết Annotation `@WebServlet`

##### Cách 1: Cấu hình nhanh 1 URL (Phổ biến nhất)
```java
@WebServlet("/hello")
public class HelloServlet extends HttpServlet { ... }
```

##### Cách 2: Cấu hình nhiều URL cho cùng 1 Servlet
```java
@WebServlet(urlPatterns = {"/hello", "/xin-chao", "/greeting"})
public class HelloServlet extends HttpServlet { ... }
```

##### Cách 3: Cấu hình đầy đủ các thuộc tính
```java
@WebServlet(
    name = "helloServlet",
    urlPatterns = {"/hello", "/chao"},
    loadOnStartup = 1
)
public class HelloServlet extends HttpServlet { ... }
```

### 4. So sánh toàn diện: Cấu hình XML vs Annotation

| Tiêu chí | Cấu hình bằng XML (`web.xml`) | Cấu hình bằng Annotation (`@WebServlet`) |
| :--- | :--- | :--- |
| **Phiên bản hỗ trợ** | Servlet 1.0 trở đi (Mọi phiên bản) | Servlet 3.0 trở đi (Hiện đại) |
| **Vị trí cấu hình** | Tập trung tại file duy nhất `web.xml` | Phân tán ngay trên đầu mỗi file Servlet class Java |
| **Tốc độ code** | Chậm hơn (phải mở file XML, gõ đúng tên package và class) | Rất nhanh và gọn gàng (chỉ 1 dòng `@WebServlet("/path")`) |
| **Refactor / Đổi tên class** | Dễ lỗi: Nếu đổi tên class mà quên sửa `web.xml` sẽ bị lỗi `ClassNotFoundException` | IDE tự động cập nhật, an toàn tuyệt đối |
| **Thay đổi URL khi deploy** | <mark style="background:#affad1">Rất linh hoạt:</mark> Có thể sửa URL trực tiếp trên server mà **không cần biên dịch (compile) lại code Java** | Muốn sửa URL phải sửa mã nguồn Java và **compile/build lại toàn bộ project** |
| **Mức độ phổ biến hiện nay** | Ít dùng cho Servlet đơn lẻ, thường chỉ dùng cho cấu hình hệ thống toàn cục | **Được dùng phổ biến nhất** trong hầu hết dự án Java Web hiện nay |

### 5. Quy tắc ưu tiên (Precedence / Conflict Resolution)

> [!IMPORTANT] Điều gì xảy ra nếu một Servlet VỪA dùng `@WebServlet` VỪA được khai báo trong `web.xml`?
> - **Quy tắc:** <mark style="background:#ffd9b3">**Cấu hình trong `web.xml` LUÔN CÓ ĐỘ ƯU TIÊN CAO HƠN và sẽ GHI ĐÈ (Override) Annotation.**</mark>
> - **Ví dụ:**
>   - Trong code Java: `@WebServlet("/hello-annotation")`
>   - Trong `web.xml`: cấu hình URL là `/hello-xml`
>   - **Kết quả:** Tomcat sẽ dùng `/hello-xml` để định tuyến, bỏ qua cấu hình trong annotation.
> - **Ý nghĩa thực tế:** Giúp đội ngũ vận hành (DevOps/SysAdmin) có thể can thiệp thay đổi cấu hình trên môi trường Production thông qua file `web.xml` mà không cần yêu cầu Developer sửa mã nguồn và build lại ứng dụng.

### 6. Khi nào nên dùng cách nào?

- **Nên dùng `@WebServlet` (Annotation) khi:**
  - Phát triển ứng dụng mới, code các Servlet chức năng thông thường.
  - Muốn code gọn gàng, tăng tốc độ phát triển, tránh mất công quản lý file XML cồng kềnh.
- **Nên dùng `web.xml` (XML Configuration) khi:**
  - Cần cấu hình các thông số toàn cục của toàn bộ ứng dụng (Application Context Params).
  - Cần cấu hình thứ tự Filter (`Filter Mapping`), Welcome file list (`<welcome-file-list>`), trang báo lỗi tùy chỉnh (`<error-page>`).
  - Bảo trì hoặc tích hợp các hệ thống Legacy (hệ thống cũ chạy Servlet 2.x).
