### 1. Bản chất cốt lõi: Forward vs SendRedirect

Trong lập trình Java Web, cả **`Forward`** và **`SendRedirect`** đều dùng để điều hướng người dùng từ trang này sang trang khác, nhưng **cơ chế hoạt động bên dưới hoàn toàn trái ngược nhau**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. FORWARD (Server-side Navigation):                                        │
│    - Diễn ra NỘI BỘ trong lòng Server (Tomcat).                             │
│    - Trình duyệt (Client) HOÀN TOÀN KHÔNG BIẾT Server đã chuyển sang trang nào.│
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. SENDREDIRECT (Client-side Navigation):                                   │
│    - Server gửi lệnh về bảo Trình duyệt TỰ GỬI 1 REQUEST MỚI sang URL khác.  │
│    - Trình duyệt (Client) BIẾT RÕ và chủ động chuyển hướng.                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

---

### 2. Sơ đồ luồng hoạt động (Visual Flow)

#### 2.1. Cơ chế `Forward` (`req.getRequestDispatcher().forward()`)
> **Chỉ có 1 Request và 1 Response duy nhất.**

```
Client (Trình duyệt)                   Tomcat Server
      │                                      │
      │ ─── 1. GET /login ─────────────────► │ ──► (LoginServlet)
      │                                      │          │
      │                                      │    Chuyển tiếp nội bộ
      │                                      │          ▼
      │                                      │     (login.jsp)
      │                                      │          │
      │ ◄── 2. Response HTML ─────────────── │ ◄────────┘
      │
 (URL trên trình duyệt: GIỮ NGUYÊN /login)
```

---

#### 2.2. Cơ chế `SendRedirect` (`resp.sendRedirect()`)
> **Có 2 Request và 2 Response riêng biệt.**

```
Client (Trình duyệt)                   Tomcat Server
      │                                      │
      │ ─── 1. POST /do-login ─────────────► │ ──► (AuthServlet xử lý)
      │                                      │          │
      │ ◄── 2. Response 302 Found ────────── │ ◄── resp.sendRedirect("/home")
      │        (Location: /home)             │
      │                                      │
      │ ─── 3. GET /home (Tự động gửi) ────► │ ──► (HomeServlet / home.jsp)
      │                                      │          │
      │ ◄── 4. Response 200 OK ───────────── │ ◄────────┘
      │
 (URL trên trình duyệt: ĐỔI THÀNH /home)
```

---

### 3. Bảng so sánh chi tiết toàn diện

| Tiêu chí | `RequestDispatcher.forward()` | `HttpServletResponse.sendRedirect()` |
| :--- | :--- | :--- |
| **Bản chất** | Điều hướng phía **Server (Server-side)** | Điều hướng phía **Client (Client-side)** |
| **Cú pháp gọi** | `req.getRequestDispatcher("/path").forward(req, resp);` | `resp.sendRedirect(req.getContextPath() + "/path");` |
| **Số chu kỳ Request / Response** | **1 Request & 1 Response** | **2 Request & 2 Response** |
| **Mã HTTP Status Code** | `200 OK` (Hoặc status của trang đích) | `302 Found` (Hoặc 301 Moved Permanently) |
| **URL trên thanh địa chỉ** | <mark style="background:#affad1">**Giữ nguyên URL ban đầu**</mark> | <mark style="background:#ffd9b3">**Thay đổi sang URL mới**</mark> |
| **Dữ liệu trong `req.setAttribute()`** | <mark style="background:#affad1">**Còn nguyên vẹn**</mark> (vì dùng chung 1 request) | <mark style="background:#ffb3b3">**Bị mất sạch**</mark> (vì request thứ 2 là request mới toanh) |
| **Phạm vi điều hướng** | **Chỉ trong nội bộ cùng ứng dụng web** | **Bất kỳ đâu** (nội bộ hoặc sang domain ngoài như `https://google.com`, `vnpay.vn`) |
| **Tốc độ / Hiệu năng** | **Nhanh hơn** (xử lý ngay trong RAM của server) | **Chậm hơn** (phải gửi qua lại 2 vòng mạng Internet) |

### 4. Khi nào nên dùng cái nào? (Best Practices)

#### 4.1. Khi nào BẮT BUỘC dùng `forward()`?

1. **Mô hình MVC (Servlet $\rightarrow$ JSP):**
   - Servlet xử lý logic, lấy dữ liệu từ DB gán vào `req.setAttribute("data", list)`.
   - Sau đó `forward` sang JSP để JSP đọc dữ liệu hiển thị HTML.
2. **Khi Form Validation thất bại (Báo lỗi nhập liệu):**
   - Người dùng nhập thiếu thông tin, bạn muốn giữ lại dữ liệu họ vừa gõ (`oldInput`) và hiển thị thông báo lỗi màu đỏ trên trang form.

```java
// Ví dụ: Báo lỗi nhập liệu
req.setAttribute("errorMessage", "Email không đúng định dạng!");
req.setAttribute("oldEmail", email);
req.getRequestDispatcher("/register.jsp").forward(req, resp);
```

---

#### 4.2. Khi nào BẮT BUỘC dùng `sendRedirect()`?

1. **Sau khi thực hiện thao tác Thêm / Sửa / Xóa (Mô hình Post-Redirect-Get - PRG Pattern):**
   - Sau khi trừ tiền, đặt hàng hoặc xóa bản ghi thành công, bạn **phải redirect** sang trang danh sách.
   - *Lý do:* Nếu dùng `forward`, khi người dùng bấm phím **F5 (Reload)**, trình duyệt sẽ gửi lại lệnh POST và khiến hành động thêm/xóa/trừ tiền bị lặp lại lần 2 (**Double Submit Bug**)!
2. **Chưa đăng nhập / Hết phiên làm việc (Session Timeout):**
   - Đẩy người dùng văng ra trang đăng nhập: `resp.sendRedirect(req.getContextPath() + "/login.jsp")`.
3. **Đăng xuất (Logout):**
   - Hủy session và chuyển hướng về trang chủ.
4. **Chuyển hướng sang bên thứ ba:**
   - Chuyển sang Cổng thanh toán VNPay, MoMo, ZaloPay, hoặc OAuth Login với Google/Facebook.

```java
// Ví dụ: Đặt hàng thành công -> Chuyển hướng sang trang hóa đơn
orderService.createOrder(cart);
resp.sendRedirect(req.getContextPath() + "/order-success");
```

### 5. 3 Lỗi phổ biến "chết người" cần tránh khi lập trình

#### ⚠️ Lỗi 1: Quên lệnh `return;` sau khi điều hướng
Cả `forward` và `sendRedirect` **không tự động dừng hàm hiện tại**. Code phía sau vẫn tiếp tục chạy nếu bạn không gõ `return;`:

```java
// SAI: Có thể gây lỗi IllegalStateException
if (user == null) {
    resp.sendRedirect(req.getContextPath() + "/login");
}
// Code bên dưới VẪN CHẠY và gây lỗi NullPointerException!
user.updateProfile(); 

// ĐÚNG:
if (user == null) {
    resp.sendRedirect(req.getContextPath() + "/login");
    return; // Dừng ngay lập tức!
}
```

#### ⚠️ Lỗi 2: Quên `req.getContextPath()` trong `sendRedirect()`
- Với `req.getRequestDispatcher("/home.jsp")`: Đường dẫn `/` đã tự hiểu là từ gốc ứng dụng.
- Nhưng với `resp.sendRedirect("/home.jsp")`: Đường dẫn `/` sẽ bị hiểu là gốc của toàn Server (`http://localhost:8080/home.jsp`) $\rightarrow$ **Lỗi 404!**
- **Quy tắc:** Luôn viết: `resp.sendRedirect(req.getContextPath() + "/home.jsp");`.

#### ⚠️ Lỗi 3: Gọi `forward()` sau khi Response đã bị gửi đi (Committed)
Nếu bạn đã gọi `resp.getWriter().flush()` hoặc xuất dữ liệu HTML ra client rồi mà sau đó lại gọi `forward()`, Server sẽ ném lỗi:
`java.lang.IllegalStateException: Cannot forward after response has been committed`.
