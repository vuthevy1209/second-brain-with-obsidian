# Servlet Context (Application Scope)

Trong Java Web, **ServletContext** là một đối tượng duy nhất đại diện cho toàn bộ ứng dụng web (Application). Nó được máy chủ Tomcat tạo ra khi ứng dụng bắt đầu khởi động (Deploy) và bị hủy khi ứng dụng tắt (Shutdown/Undeploy).

Bởi vì nó là **DUY NHẤT** đối với toàn bộ ứng dụng, bất kỳ dữ liệu nào lưu vào ServletContext đều mang tính chất **Toàn cục (Global)** – mọi Servlet, mọi người dùng (Session), mọi luồng xử lý đều có thể nhìn thấy và truy cập chung một dữ liệu đó.

---

## 1. Cách lấy đối tượng ServletContext

Trong bất kỳ Servlet nào (kế thừa `HttpServlet`), bạn có thể lấy ServletContext dễ dàng qua câu lệnh:

```java
// Cách 1: Phổ biến nhất (Trong Servlet)
ServletContext context = getServletContext();

// Cách 2: Lấy thông qua đối tượng Request
ServletContext context = req.getServletContext();

// Cách 3: Lấy thông qua đối tượng Session
ServletContext context = req.getSession().getServletContext();
```

---

## 2. Ứng dụng thực tế của ServletContext

### 2.1. Lưu trữ và Chia sẻ dữ liệu toàn cục (Application Scope)
Đây là tính năng hay dùng nhất.
- **Tình huống:** Bạn muốn lưu tổng số lượt truy cập của trang web (View Count). Hoặc đếm số người đang online. Dữ liệu này là chung cho mọi khách hàng.
- **Cách làm:**
```java
// 1. Lưu dữ liệu chung vào Context
getServletContext().setAttribute("totalViews", 1000);

// 2. Lấy dữ liệu ra (Ở một Servlet khác, hoặc người dùng khác)
Integer views = (Integer) getServletContext().getAttribute("totalViews");
```
- **Lấy ra ở file JSP:**
```jsp
<p>Tổng số lượt xem trang: ${applicationScope.totalViews}</p>
```
*(Trong EL, ServletContext được gọi là `applicationScope`)*

### 2.2. Đọc cấu hình chung từ file `web.xml`
Bạn có thể định nghĩa các tham số cấu hình dùng chung cho toàn bộ Web App trong `web.xml` bằng thẻ `<context-param>`, sau đó dùng ServletContext để đọc ra.

**Trong `web.xml`:**
```xml
<context-param>
    <param-name>adminEmail</param-name>
    <param-value>support@congty.com</param-value>
</context-param>
```

**Trong Java Servlet:**
```java
String email = getServletContext().getInitParameter("adminEmail");
```

### 2.3. Lấy đường dẫn thực tế (Real Path) trên Server
Khi bạn làm tính năng **Upload File**, bạn cần biết đường dẫn thư mục gốc vật lý trên máy chủ (Ví dụ: `C:/xampp/tomcat/webapps/my-app/uploads`) thay vì đường dẫn web ảo (`http://localhost/uploads`).

```java
// Trả về đường dẫn vật lý thực tế trỏ tới thư mục /uploads của dự án
String realPath = getServletContext().getRealPath("/uploads");
File folder = new File(realPath);
```

## 3. So sánh 3 phạm vi (Scope) quan trọng nhất

Để không bị nhầm lẫn, đây là bảng so sánh sự khác biệt khi bạn dùng `setAttribute()` ở các nơi khác nhau:

| Tiêu chí | Request Scope (`HttpServletRequest`) | Session Scope (`HttpSession`) | Application Scope (`ServletContext`) |
| :--- | :--- | :--- | :--- |
| **Vòng đời** | Sống - chết theo 1 cú click chuột (1 Request - 1 Response). | Sống - chết theo 1 người dùng (Thường là 30 phút idle hoặc Logout). | Sống - chết theo sự tồn tại của Server (Tomcat). |
| **Chia sẻ cho ai?** | Chỉ chia sẻ giữa Servlet và file JSP được `forward` tới. Dành riêng cho 1 luồng xử lý. | Chia sẻ chung cho **MỘT** người dùng (Client/Browser) xuyên suốt nhiều trang web. | Chia sẻ chung cho **TẤT CẢ** người dùng, tất cả Servlet trong hệ thống. |
| **Ví dụ thực tế** | Câu thông báo "Đăng nhập thất bại", Form bị lỗi. | Trạng thái "Đã đăng nhập", Giỏ hàng (Cart) của người mua. | Đếm số lượng truy cập, Đường dẫn Database chung, Cấu hình web. |
| **EL lấy dữ liệu** | `${requestScope.xyz}` | `${sessionScope.xyz}` | `${applicationScope.xyz}` |

> [!WARNING] Cảnh báo Bảo mật
> Vì ServletContext là nơi chứa "Dữ liệu chung", **TUYỆT ĐỐI KHÔNG** lưu trữ thông tin cá nhân của người dùng (như thẻ tín dụng, user profile, password) vào đây. Nếu không, toàn bộ người dùng khác sẽ nhìn thấy thông tin của nhau, dẫn đến thảm họa rò rỉ dữ liệu. Thông tin cá nhân phải được lưu trong **Session**.
