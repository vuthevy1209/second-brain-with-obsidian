# Servlet Filter và Listener

Đây là hai vũ khí cực kỳ lợi hại trong Java Web để can thiệp vào vòng đời của một Request và toàn bộ ứng dụng (Application Lifecycle) mà không cần phải sửa code của từng Servlet đơn lẻ.

---

### 1. Filter (Bộ lọc)

Filter giống như "bảo vệ cổng". Bất kỳ Request nào đi từ Trình duyệt vào Servlet (hoặc Response đi từ Servlet ra Trình duyệt) đều phải bước qua xác của Filter.

**Tác dụng phổ biến:**
- **Auth Filter:** Kiểm tra xem người dùng đã Đăng nhập chưa? Nếu chưa thì đá văng ra trang Login mà không cho vào Controller.
- **Role Filter:** Kiểm tra quyền (Admin/User).
- **Encoding Filter:** Ép kiểu tiếng Việt (UTF-8) cho mọi Request để chống lỗi font.
- **Logging Filter:** Ghi log xem ai vừa truy cập vào đường dẫn nào, tốn bao nhiêu mili-giây.
#### Cách hoạt động: Chain of Responsibility (Chuỗi trách nhiệm)
Nhiều Filter có thể xếp chồng lên nhau thành một chuỗi (Chain). 
- Filter A (Log) -> Filter B (UTF-8) -> Filter C (Kiểm tra Đăng nhập) -> Tới Servlet.

#### Ví dụ Code Auth Filter:
```java
@WebFilter("/*") // Áp dụng cho mọi đường dẫn
public class AuthFilter implements Filter {

    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) 
            throws IOException, ServletException {
        
        HttpServletRequest req = (HttpServletRequest) request;
        HttpServletResponse res = (HttpServletResponse) response;
        
        // 1. Kiểm tra session
        HttpSession session = req.getSession(false);
        boolean isLoggedIn = (session != null && session.getAttribute("user") != null);
        
        // 2. Cho phép đi qua nếu đã login, hoặc đang truy cập trang login
        if (isLoggedIn || req.getRequestURI().contains("/login")) {
            // Lệnh QUAN TRỌNG NHẤT: Cho phép đi tiếp (qua Filter khác hoặc tới Servlet)
            chain.doFilter(request, response);
        } else {
            // Chưa login -> Đá về trang chủ
            res.sendRedirect("/login");
        }
    }
}
```

> [!WARNING] Lỗi cực kỳ kinh điển
> Trong hàm `doFilter()`, nếu bạn đã cho phép Request hợp lệ đi tiếp thì BẮT BUỘC phải gọi lệnh `chain.doFilter(request, response);`. 
> Nếu quên dòng này, Request sẽ bị "tắc" tại Filter và màn hình trình duyệt sẽ trắng bóc!

### 2. Listener (Người lắng nghe)

Listener là những class ngồi "chầu chực" chờ các sự kiện (Event) trong vòng đời của Web App xảy ra để thực thi một tác vụ ngầm.

**Các loại Listener phổ biến:**
1. `ServletContextListener`: Lắng nghe sự kiện khi Tomcat vừa **khởi động xong** (Deploy) hoặc sắp **tắt** (Shutdown).
   - *Ứng dụng:* Khởi tạo Connection Pool (Hồ chứa kết nối Database), đọc file cấu hình chung.
2. `HttpSessionListener`: Lắng nghe sự kiện khi có một phiên truy cập (Session) vừa được **tạo ra** hoặc bị **hủy bỏ** (Timeout/Logout).
   - *Ứng dụng:* Đếm số lượng người đang Online hiện tại.

#### Ví dụ Đếm người Online:
```java
@WebListener
public class SessionCounterListener implements HttpSessionListener {
    // Biến toàn cục lưu số người
    private static int activeUsers = 0;

    @Override
    public void sessionCreated(HttpSessionEvent se) {
        // Có ông khách mới vào web
        activeUsers++;
        System.out.println("Một người dùng vừa truy cập. Đang online: " + activeUsers);
    }

    @Override
    public void sessionDestroyed(HttpSessionEvent se) {
        // Ông khách tắt trình duyệt quá 30 phút, hoặc bấm Đăng xuất
        activeUsers--;
        System.out.println("Một người dùng đã rời đi. Đang online: " + activeUsers);
    }
}
```
