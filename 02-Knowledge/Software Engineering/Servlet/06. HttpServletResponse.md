### 1. Tổng quan về HttpServletResponse

> [!NOTE] Định nghĩa cốt lõi
> `HttpServletResponse` là một Interface thuộc gói `jakarta.servlet.http` (hoặc `javax.servlet.http`), đại diện cho **toàn bộ dữ liệu phản hồi (HTTP Response)** mà Server chuẩn bị và gửi trả lại cho Client (Trình duyệt, Postman, Mobile App).

- **Cơ chế khởi tạo:** Được Servlet Container (Tomcat) tạo cùng lúc với `HttpServletRequest` và truyền vào các hàm `service()`, `doGet()`, `doPost()`,...
- **Nhiệm vụ chính:** Cho phép lập trình viên:
  1. Thiết lập **Mã trạng thái HTTP (Status Code)** (200, 404, 500,...).
  2. Thiết lập các **Response Headers** (Content-Type, Cookie, Cache,...).
  3. Ghi dữ liệu nội dung trả về **Response Body** (HTML, JSON, File ảnh/PDF,...).
  4. Điều hướng trình duyệt chuyển trang (**Redirect**).

```
       ┌──────────────────┐
       │  HelloServlet    │ ──► doGet(HttpServletRequest req, HttpServletResponse resp)
       └────────┬─────────┘
                │
                │ Ghi dữ liệu vào resp
                ▼
       ┌──────────────────┐
       │  Apache Tomcat   │ ──► Đóng gói thành gói tin HTTP Response
       └────────┬─────────┘
                │
                │ Gửi qua mạng Internet
                ▼
       [Client / Trình duyệt]
```

### 2. Cấu trúc của một HTTP Response

Gói tin phản hồi HTTP được gửi về Client bao gồm 3 thành phần chính:

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. STATUS LINE:   HTTP/1.1 200 OK                                      │
├────────────────────────────────────────────────────────────────────────┤
│ 2. HEADERS:                                                            │
│    Content-Type: text/html; charset=UTF-8                              │
│    Content-Length: 1024                                                │
│    Set-Cookie: token=xyz987; HttpOnly; Path=/                          │
│    Cache-Control: no-cache                                             │
├────────────────────────────────────────────────────────────────────────┤
│ 3. BODY:                                                               │
│    <h1>Xin chào người dùng!</h1> hoặc {"status": "success"}            │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. Các nhóm phương thức quan trọng trong HttpServletResponse

#### 3.1. Nhóm 1: Thiết lập Mã trạng thái (Status Code)

```java
// Thiết lập Status Code thành công (Mặc định là 200 OK)
resp.setStatus(HttpServletResponse.SC_OK);          // 200
resp.setStatus(HttpServletResponse.SC_CREATED);     // 201 (Khi tạo mới dữ liệu thành công)

// Gửi lỗi về cho Client kèm thông báo
resp.sendError(HttpServletResponse.SC_NOT_FOUND, "Không tìm thấy tài nguyên yêu cầu!"); // 404
resp.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Bạn chưa đăng nhập!");             // 401
resp.sendError(HttpServletResponse.SC_FORBIDDEN, "Bạn không có quyền truy cập!");       // 403
```

#### 3.2. Nhóm 2: Thiết lập Content-Type & Bảng mã (Character Encoding)

<mark style="background:#affad1">Luôn luôn thiết lập Content-Type TRƯỚC KHI lấy Stream ghi dữ liệu (`getWriter()` hoặc `getOutputStream()`):</mark>

```java
// 1. Trả về giao diện HTML có tiếng Việt
resp.setContentType("text/html;charset=UTF-8");

// 2. Trả về dữ liệu JSON (REST API)
resp.setContentType("application/json;charset=UTF-8");

// 3. Trả về file văn bản thuần
resp.setContentType("text/plain;charset=UTF-8");
```

#### 3.3. Nhóm 3: Ghi dữ liệu trả về (Output Stream)

Có 2 cách ghi dữ liệu trả về tùy thuộc vào loại nội dung:

##### Cách 1: Dùng `getWriter()` (Dành cho Văn bản dạng Text: HTML, JSON, XML)
```java
resp.setContentType("application/json;charset=UTF-8");
PrintWriter out = resp.getWriter();
out.print("{\"id\": 1, \"name\": \"Nguyen Van A\"}");
out.flush();
```

##### Cách 2: Dùng `getOutputStream()` (Dành cho Dữ liệu Nhị phân Binary: Download file, Ảnh, PDF, Excel)
```java
resp.setContentType("application/pdf");
resp.setHeader("Content-Disposition", "attachment; filename=\"document.pdf\"");

ServletOutputStream outStream = resp.getOutputStream();
// Ghi mảng byte của file ra stream
outStream.write(pdfByteArray);
outStream.flush();
```

> [!CAUTION] Cảnh báo lỗi `IllegalStateException`
> Trong cùng một request, bạn **CHỈ ĐƯỢC CHỌN 1 TRONG 2**: hoặc gọi `getWriter()`, hoặc gọi `getOutputStream()`. Nếu gọi cả hai trên cùng một đối tượng `resp`, Servlet Container sẽ ném ra ngoại lệ:
> `java.lang.IllegalStateException: getWriter() has already been called for this response`

#### 3.4. Nhóm 4: Thiết lập Response Headers & Cookies

```java
// 1. Thêm hoặc ghi đè Header
resp.setHeader("Custom-Header", "SecretValue123");
resp.setHeader("Cache-Control", "no-cache, no-store, must-revalidate");

// 2. Gửi Cookie về trình duyệt client lưu lại
Cookie userCookie = new Cookie("userTheme", "dark");
userCookie.setMaxAge(60 * 60 * 24 * 7); // Tồn tại 7 ngày
userCookie.setPath("/");
resp.addCookie(userCookie);
```

#### 3.5. Nhóm 5: Chuyển hướng Client (`sendRedirect`)

Yêu cầu trình duyệt của Client tự động gửi một request mới sang một địa chỉ URL khác:

```java
// 1. Chuyển hướng nội bộ trong cùng ứng dụng
resp.sendRedirect(req.getContextPath() + "/login.jsp");

// 2. Chuyển hướng sang một website bên ngoài hoàn toàn
resp.sendRedirect("https://google.com");
```

### 4. Bảng so sánh kinh điển: `forward()` vs `sendRedirect()`

Đây là câu hỏi xuất hiện ở hầu hết các buổi phỏng vấn Java Web / Servlet:

```
[FORWARD - Server làm việc nội bộ]
Client ──── 1 Request ────► Servlet ──── Forward nội bộ ────► JSP
Client ◄── 1 Response ──────────────────────────────────────┘
(URL trên trình duyệt KHÔNG đổi)

[REDIRECT - Client gửi 2 Request riêng biệt]
Client ──── 1 Request ────► Servlet (Xử lý xong)
Client ◄── Response 302 (Location: /login) ──┘
Client ──── 2 Request ────► URL mới (/login) ──► Server
Client ◄── Response 200 ────────────────────────┘
(URL trên trình duyệt THAY ĐỔI sang /login)
```

| Tiêu chí | `RequestDispatcher.forward()` | `HttpServletResponse.sendRedirect()` |
| :--- | :--- | :--- |
| **Đối tượng gọi** | Gọi từ `HttpServletRequest` | Gọi từ `HttpServletResponse` |
| **Số lượng Request/Response** | **1 Request & 1 Response** duy nhất | **2 Request & 2 Response** riêng biệt (Mã HTTP 302) |
| **URL trên thanh địa chỉ** | **Giữ nguyên** (Client không biết Server đã chuyển sang trang nào) | **Thay đổi** thành URL mới |
| **Chia sẻ dữ liệu (`req.setAttribute`)** | **Còn giữ nguyên** (vì dùng chung 1 request) | **Bị mất dữ liệu** (vì request thứ 2 là một đối tượng mới hoàn toàn) |
| **Phạm vi chuyển hướng** | Chỉ chuyển tiếp **nội bộ bên trong cùng ứng dụng web** | Có thể chuyển hướng sang **bất kỳ URL hoặc website nào bên ngoài** |
| **Tốc độ** | Nhanh hơn (xử lý nội bộ trên Server) | Chậm hơn (phải truyền tải 2 vòng mạng Client-Server) |
| **Mục đích sử dụng** | Chuyển dữ liệu từ Controller (Servlet) sang View (JSP) để render HTML | Sau khi thực hiện hành động (Thêm/Sửa/Xóa thành công, Đăng xuất, Chưa đăng nhập) |

### 5. Bảng tổng hợp các mã HTTP Status Code thông dụng

| Mã trạng thái | Tên tiếng Anh | Ý nghĩa thực tế |
| :--- | :--- | :--- |
| **200** | `OK` | Yêu cầu xử lý thành công, trả về dữ liệu. |
| **201** | `Created` | Tạo mới tài nguyên thành công (thường dùng sau POST tạo bản ghi mới). |
| **204** | `No Content` | Xử lý thành công nhưng không có dữ liệu trả về (thường dùng cho DELETE). |
| **301** | `Moved Permanently` | Tài nguyên đã chuyển vĩnh viễn sang URL mới. |
| **302** | `Found / Temporary Redirect` | Chuyển hướng tạm thời (mặc định của `sendRedirect`). |
| **400** | `Bad Request` | Dữ liệu Client gửi lên không hợp lệ (sai định dạng, thiếu trường bắt buộc). |
| **401** | `Unauthorized` | Chưa xác thực danh tính (chưa đăng nhập hoặc token không hợp lệ). |
| **403** | `Forbidden` | Đã đăng nhập nhưng không đủ quyền hạn truy cập tài nguyên này. |
| **404** | `Not Found` | Không tìm thấy đường dẫn URL hoặc tài nguyên yêu cầu. |
| **405** | `Method Not Allowed` | Không hỗ trợ HTTP Method này (Ví dụ: Servlet chỉ có `doGet` nhưng Client gửi POST). |
| **500** | `Internal Server Error` | Server bị lỗi mã nguồn (Ngoại lệ `NullPointerException`, lỗi kết nối DB,...). |
| **503** | `Service Unavailable` | Server đang bảo trì hoặc quá tải không thể phục vụ. |

### 6. Code mẫu minh họa tổng hợp

```java
package org.example.servlet;

import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.Cookie;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.io.PrintWriter;

@WebServlet("/api/response-demo")
public class ResponseDemoServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) 
            throws ServletException, IOException {

        String type = req.getParameter("type");

        if ("redirect".equalsIgnoreCase(type)) {
            // Demo 1: Chuyển hướng sang trang hello
            resp.sendRedirect(req.getContextPath() + "/hello");
            return;
        }

        if ("json".equalsIgnoreCase(type)) {
            // Demo 2: Xuất dữ liệu JSON (REST API)
            resp.setContentType("application/json;charset=UTF-8");
            resp.setStatus(HttpServletResponse.SC_OK);

            // Ghi cookie
            Cookie visitCookie = new Cookie("lastVisit", "2026-08-08");
            resp.addCookie(visitCookie);

            try (PrintWriter out = resp.getWriter()) {
                out.print("{\"status\": 200, \"message\": \"Thành công!\"}");
            }
            return;
        }

        // Demo 3: Trả về trang HTML trực tiếp
        resp.setContentType("text/html;charset=UTF-8");
        try (PrintWriter out = resp.getWriter()) {
            out.println("<h1>Demo HttpServletResponse</h1>");
            out.println("<p>Trạng thái HTTP: 200 OK</p>");
        }
    }
}
```
