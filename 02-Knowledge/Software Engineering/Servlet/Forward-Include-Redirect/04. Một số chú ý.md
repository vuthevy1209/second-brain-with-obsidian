# Tổng hợp các chú ý quan trọng (Best Practices & Lỗi)

### 1. Bảng so sánh kinh điển: Forward vs Redirect

| Tiêu chí | `Forward` | `SendRedirect` |
| :--- | :--- | :--- |
| **URL trình duyệt** | Giữ nguyên | Bị thay đổi sang trang mới |
| **Dữ liệu `setAttribute`**| Còn nguyên vẹn | Bị xóa sạch hoàn toàn |
| **Phạm vi** | Chỉ trong nội bộ Server | Ra bất kỳ đâu (Google, Facebook, VNPay) |
| **Tốc độ** | Rất nhanh | Chậm hơn (Mất 1 vòng truyền tải mạng) |
| **Ứng dụng chính** | Chuyển dữ liệu sang JSP hiển thị | Chống bấm F5 gửi lại Form (PRG Pattern), Đăng xuất |

---

### 2. Cạm bẫy lỗi 500 kinh điển: Dùng chung Include và Forward

Nếu bạn cố tình kết hợp `include` (hoặc in ra màn hình quá nhiều) rồi mới gọi `forward()` trong cùng 1 request:
```java
req.getRequestDispatcher("/common/header.jsp").include(req, resp);
out.flush(); // Cố tình xuất data ra mạng
req.getRequestDispatcher("/target.jsp").forward(req, resp); // BÙM! LỖI
```

**Tomcat sẽ ném lỗi:**
👉 `java.lang.IllegalStateException: Cannot forward after response has been committed`

**Nguyên nhân sâu xa:** 
Bản chất của `forward` là: *"Xóa sạch những gì thằng trước làm để tự tôi vẽ từ đầu"*. Nhưng do bạn đã dùng `include` và làm trào Buffer (`flush`), gói tin Response **đã bắt đầu được gửi đi qua mạng Internet** về trình duyệt. Server không thể nào "rút" gói tin đó lại để xóa được nữa, nên nó đành báo lỗi!

> [!WARNING] Luật sinh tồn trong Servlet
> - Đã `forward` thì **không in** ra màn hình nữa.
> - Đã in ra màn hình (hoặc `include`) thì **tuyệt đối không** `forward`.

### 3. Đừng quên lệnh `return;` sau khi điều hướng

Cả `forward` lẫn `sendRedirect` **không tự động dừng hàm Java**.

```java
// SAI: Code nhạy cảm bên dưới vẫn chạy dù đã báo lỗi!
if (user == null) {
    resp.sendRedirect(req.getContextPath() + "/login");
}
user.deleteDatabase(); 

// ĐÚNG:
if (user == null) {
    resp.sendRedirect(req.getContextPath() + "/login");
    return; // Phải có lệnh này để dừng hàm ngay lập tức!
}
```
