# Xử lý ngoại lệ toàn cục (Global Exception Handling)

Trong quá trình ứng dụng hoạt động, các lỗi như `NullPointerException`, lỗi Database (`SQLException`), hoặc người dùng truy cập trang không tồn tại (Lỗi 404) là điều không thể tránh khỏi.
Thay vì để Tomcat văng ra một trang trắng có chứa các dòng "Stack Trace" nhìn rất đáng sợ và thiếu chuyên nghiệp, chúng ta có thể gom toàn bộ lỗi về một chỗ để xử lý chung.

Khái niệm này trong **Spring Framework** được thực hiện cực kỳ thanh lịch bằng Annotation `@ControllerAdvice` kết hợp `@ExceptionHandler`. Trong **Servlet thuần**, chúng ta có thể làm được điều tương tự nhờ vào sự kết hợp giữa cấu hình `web.xml` và một **Servlet Đóng vai trò làm Controller Advice**.

---

## 1. Ánh xạ khái niệm (Servlet vs Spring)

| Servlet Thuần | Spring Framework |
| :--- | :--- |
| Khai báo thẻ `<error-page>` trong `web.xml`. | Dùng Annotation `@ControllerAdvice` để đánh dấu class bắt lỗi toàn cục. |
| Một `ExceptionHandlerServlet` xử lý các attribute báo lỗi từ Request. | Dùng `@ExceptionHandler(Exception.class)` để bắt chính xác loại Exception. |
| Tomcat tự động bắt lỗi ở bất cứ đâu và quăng request về trang xử lý. | Spring tự động hứng Exception khi nó bị quăng ra khỏi Controller. |

---

## 2. Cách triển khai trong Servlet (Giống @ControllerAdvice)

### Bước 1: Khai báo bộ "bắt dính" lỗi trong `web.xml`
Bạn sẽ nói với Tomcat rằng: *"Ê Tomcat, hễ ứng dụng văng ra lỗi 404, hoặc bị dính bất kỳ cái `java.lang.Exception` nào, thì làm ơn ném cái Request đó sang cho đường dẫn `/handle-error` xử lý giùm tao!"*

```xml
<!-- Trong web.xml -->

<!-- Bắt theo mã HTTP Status (Ví dụ: 404 Not Found) -->
<error-page>
    <error-code>404</error-code>
    <location>/handle-error</location>
</error-page>

<!-- Bắt theo loại Exception (Giống hệt @ExceptionHandler(Exception.class)) -->
<error-page>
    <exception-type>java.lang.Exception</exception-type>
    <location>/handle-error</location>
</error-page>
```

### Bước 2: Tạo Servlet đóng vai trò như `@ControllerAdvice`
Chúng ta tạo một Servlet có đường dẫn là `/handle-error`. Khi Request bay vào đây, Tomcat đã ngầm nhét sẵn một đống dữ liệu về cái lỗi đó vào trong `HttpServletRequest` rồi. Nhiệm vụ của ta chỉ là bới nó ra.

```java
@WebServlet("/handle-error")
public class GlobalExceptionHandlerServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) 
            throws ServletException, IOException {
        processError(req, resp);
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) 
            throws ServletException, IOException {
        processError(req, resp);
    }

    private void processError(HttpServletRequest req, HttpServletResponse resp) 
            throws ServletException, IOException {
            
        // 1. Lấy thông tin chi tiết về lỗi do Tomcat nhét vào
        Throwable throwable = (Throwable) req.getAttribute("jakarta.servlet.error.exception");
        Integer statusCode = (Integer) req.getAttribute("jakarta.servlet.error.status_code");
        String servletName = (String) req.getAttribute("jakarta.servlet.error.servlet_name");
        String requestUri = (String) req.getAttribute("jakarta.servlet.error.request_uri");

        if (servletName == null) servletName = "Unknown";
        if (requestUri == null) requestUri = "Unknown";

        // 2. Phân tích loại lỗi (Tương đương việc chia hàm trong @ControllerAdvice)
        String errorMessage = "Đã xảy ra lỗi không xác định.";
        
        if (statusCode == 404) {
            errorMessage = "Trang bạn tìm kiếm không tồn tại (404)!";
        } else if (throwable != null) {
            // Nếu có lỗi Exception, ta log lại để Dev sửa
            System.out.println("❌ GLOBAL ERROR CATCHER: Lỗi tại " + requestUri);
            throwable.printStackTrace(); // In ra console cho lập trình viên xem
            
            // Còn đây là câu nói nhẹ nhàng cho User xem
            errorMessage = "Hệ thống đang gặp sự cố, xin thử lại sau. (" + throwable.getMessage() + ")";
        }

        // 3. Quăng dữ liệu sang cho View (JSP) hiển thị thông báo đẹp mắt
        req.setAttribute("loiHienTai", errorMessage);
        req.getRequestDispatcher("/views/error.jsp").forward(req, resp);
    }
}
```

### Bước 3: File View (error.jsp) chỉ hiển thị phần ngọn
Đây là nơi User nhìn thấy, chúng ta phải làm giao diện thân thiện, không dọa khách hàng.

```jsp
<%@ page contentType="text/html;charset=UTF-8" language="java" %>
<html>
<head>
    <title>Ối! Có lỗi rồi</title>
</head>
<body>
    <div style="text-align: center; margin-top: 50px;">
        <h1 style="color: red;">Rất tiếc! Đã có lỗi xảy ra 😭</h1>
        
        <!-- Hiển thị thông báo mềm mỏng lấy từ GlobalExceptionHandlerServlet -->
        <p>${loiHienTai}</p>
        
        <a href="${pageContext.request.contextPath}/">Về trang chủ</a>
    </div>
</body>
</html>
```

---

> [!TIP] Bản chất thực sự
> Thay vì copy-paste khối lệnh `try - catch` đi khắp mọi nơi trong tất cả các Servlet, cách cấu hình Global Exception này giúp code Servlet của bạn cực kỳ sạch sẽ. 
> Trong Servlet, cứ có lỗi là bạn cứ ngang nhiên `throw new Exception()` hoặc quăng lỗi không kiểm soát cũng được. Tomcat sẽ chịu trách nhiệm bắt cái lỗi văng ra đó, gói lại và gọi hàm "Cấp cứu" (`/handle-error`) để bạn tự xử lý "bầu tâm sự" cuối cùng với khách hàng. 
> Cơ chế này chính là nguồn cảm hứng làm nên `@ControllerAdvice` tuyệt vời của Spring sau này.
