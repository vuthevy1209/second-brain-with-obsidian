# 🛡️ IPS — Intrusion Prevention System (Phát hiện và Chặn)

## 1. IPS là gì?

**IPS (Intrusion Prevention System)** là hệ thống bảo mật mạng có khả năng **phát hiện VÀ tự động chặn** các cuộc tấn công trong thời gian thực (real-time). IPS là bước tiến hóa của IDS — không chỉ cảnh báo mà còn **hành động ngay lập tức**.

> 💡 **Ví dụ đơn giản:** Nếu IDS là camera an ninh (chỉ quay và báo động), thì IPS là **bảo vệ có vũ trang** — vừa phát hiện kẻ xâm nhập, vừa **chặn lại ngay**.

---

## 2. IDS vs IPS — So sánh chi tiết

| Tiêu chí              | IDS                                | IPS                                       |
| --------------------- | ---------------------------------- | ----------------------------------------- |
| **Chức năng chính**   | Phát hiện + Cảnh báo               | Phát hiện + **Chặn tự động**              |
| **Vị trí trong mạng** | Ngoài luồng (out-of-band, passive) | Trong luồng (inline, active)              |
| **Ảnh hưởng traffic** | Không                              | Có — traffic phải đi qua IPS              |
| **Latency**           | Không thêm                         | Có thể thêm latency                       |
| **Rủi ro**            | Bỏ sót tấn công (không chặn)       | False positive → chặn nhầm traffic hợp lệ |
| **Downtime risk**     | Không                              | IPS lỗi → có thể mất kết nối              |

## 3. Phân loại IPS

### 3.1. Theo vị trí triển khai

#### a) NIPS — Network-based IPS
- Đặt **inline** trên đường mạng
- Giám sát và chặn traffic cho **toàn bộ network segment**
- Thường tích hợp trong **NGFW** (Next-Gen Firewall)
- Ví dụ: Snort (inline mode), Suricata, Cisco Firepower, Palo Alto

#### b) HIPS — Host-based IPS
- Cài trên **từng host** (server/workstation)
- Giám sát và chặn hoạt động đáng ngờ **trên host đó**
- Kiểm soát: process execution, file access, registry changes, network connections
- Ví dụ: Windows Defender Exploit Guard, OSSEC (active response), CrowdStrike Falcon

#### c) WIPS — Wireless IPS
- Giám sát **mạng không dây (WiFi)**
- Phát hiện và chặn: Rogue AP, Evil Twin, Deauth attack, WPA cracking

### 3.2. Theo phương pháp phát hiện

| Phương pháp | Mô tả | Ưu điểm | Nhược điểm |
|---|---|---|---|
| **Signature-based** | So sánh với mẫu tấn công đã biết | Chính xác, ít false positive | Không phát hiện zero-day |
| **Anomaly-based** | So sánh với baseline bình thường | Phát hiện được zero-day | Nhiều false positive |
| **Policy-based** | Dựa trên chính sách do admin định nghĩa | Linh hoạt, tùy chỉnh cao | Cần admin có kiến thức |
| **Reputation-based** | Dựa trên reputation của IP/domain | Chặn nhanh IP xấu | Phụ thuộc database bên ngoài |

## 4. Hành động của IPS khi phát hiện tấn công

| Action | Mô tả |
|---|---|
| **Drop** | Bỏ packet độc hại, không cho đi qua |
| **Reset** | Gửi TCP RST để ngắt kết nối |
| **Block** | Chặn Source IP trong một khoảng thời gian |
| **Alert** | Chỉ cảnh báo, không chặn (giống IDS mode) |
| **Allow** | Cho phép (whitelist, cho traffic đã biết an toàn) |
| **Rate Limit** | Giới hạn tốc độ traffic từ source đáng ngờ |
| **Quarantine** | Cách ly host bị nhiễm (thường trong HIPS) |
| **Redirect** | Chuyển hướng traffic đến honeypot/sandbox |

## 5. IPS trên Windows Server

### 5.1. Windows Defender Exploit Guard

Tích hợp sẵn trong Windows Server 2016/2019/2022, đóng vai trò **HIPS**:

#### a) Attack Surface Reduction (ASR) Rules
```powershell
# Chặn Office apps tạo child process
Set-MpPreference -AttackSurfaceReductionRules_Ids D4F940AB-401B-4EFC-AADC-AD5F3C50688A `
    -AttackSurfaceReductionRules_Actions Enabled

# Chặn Office apps tạo executable content
Set-MpPreference -AttackSurfaceReductionRules_Ids 3B576869-A4EC-4529-8536-B80A7769E899 `
    -AttackSurfaceReductionRules_Actions Enabled

# Chặn JavaScript/VBScript tải executable
Set-MpPreference -AttackSurfaceReductionRules_Ids D3E037E1-3EB8-44C8-A917-57927947596D `
    -AttackSurfaceReductionRules_Actions Enabled

# Chặn credential theft từ LSASS
Set-MpPreference -AttackSurfaceReductionRules_Ids 9E6C4E1F-7D60-472F-BA1A-A39EF669E4B2 `
    -AttackSurfaceReductionRules_Actions Enabled

# Xem trạng thái ASR rules
Get-MpPreference | Select-Object -ExpandProperty AttackSurfaceReductionRules_Ids
```

#### b) Controlled Folder Access
```powershell
# Bật Controlled Folder Access (chống ransomware)
Set-MpPreference -EnableControlledFolderAccess Enabled

# Thêm folder được bảo vệ
Add-MpPreference -ControlledFolderAccessProtectedFolders "C:\Important-Data"

# Thêm app được phép truy cập
Add-MpPreference -ControlledFolderAccessAllowedApplications "C:\Program Files\MyApp\app.exe"
```

#### c) Network Protection
```powershell
# Bật Network Protection (chặn kết nối đến domain/IP độc hại)
Set-MpPreference -EnableNetworkProtection Enabled

# Chế độ Audit (chỉ log, không chặn)
Set-MpPreference -EnableNetworkProtection AuditMode
```

#### d) Exploit Protection
```powershell
# Export cấu hình hiện tại
Get-ProcessMitigation -RegistryConfigFilePath "C:\backup\exploit-protection.xml"

# Import cấu hình
Set-ProcessMitigation -PolicyFilePath "C:\config\exploit-protection.xml"

# Bật DEP cho tất cả processes
Set-ProcessMitigation -System -Enable DEP

# Bật ASLR
Set-ProcessMitigation -System -Enable ForceRelocateImages
```

### 5.2. Windows Defender Application Control (WDAC)

- Kiểm soát **ứng dụng nào được phép chạy** trên server
- Thay thế **AppLocker** trong phiên bản mới
- Đóng vai trò **HIPS** ở mức application

```powershell
# Tạo policy cho phép chỉ Microsoft-signed apps
New-CIPolicy -Level Publisher -FilePath "C:\policies\BasePolicy.xml" -UserPEs

# Audit mode trước
Set-RuleOption -FilePath "C:\policies\BasePolicy.xml" -Option 3  # Audit mode

# Convert sang binary
ConvertFrom-CIPolicy -XmlFilePath "C:\policies\BasePolicy.xml" `
    -BinaryFilePath "C:\Windows\System32\CodeIntegrity\SIPolicy.p7b"
```

### 5.3. AppLocker (Application Control — HIPS)

```
AppLocker Rules:
├── Executable Rules    → .exe, .com
├── Windows Installer   → .msi, .msp
├── Script Rules        → .ps1, .bat, .cmd, .vbs, .js
├── Packaged App Rules  → Windows Store apps
└── DLL Rules           → .dll, .ocx (advanced)
```

```powershell
# Xem AppLocker rules
Get-AppLockerPolicy -Effective | Select-Object -ExpandProperty RuleCollections

# Tạo rule cho phép apps trong Program Files
New-AppLockerPolicy -RuleType Path -Path "C:\Program Files\*" `
    -Action Allow -User "Everyone"

# Export policy
Get-AppLockerPolicy -Effective -Xml | Out-File "C:\backup\applocker.xml"
```

## 7. Triển khai IPS — Chiến lược

### 7.1. Deployment Modes

| Mode | Mô tả | Use case |
|---|---|---|
| **Inline (Prevention)** | Traffic đi qua IPS, chặn ngay | Production — bảo vệ thực sự |
| **Inline (Detection/Tap)** | Traffic đi qua nhưng chỉ cảnh báo | Testing — đánh giá trước khi bật chặn |
| **Passive/Monitor** | Copy traffic (SPAN), chỉ giám sát | POC — proof of concept |

### 7.2. Fail-Open vs Fail-Close

| Mode | Khi IPS lỗi | Ưu tiên |
|---|---|---|
| **Fail-Open** | Traffic vẫn đi qua (không bảo vệ) | **Availability** (uptime) |
| **Fail-Close** | Traffic bị chặn hết | **Security** (an toàn) |

> ⚠️ **Quyết định quan trọng:** Chọn Fail-Open hay Fail-Close phụ thuộc vào yêu cầu của tổ chức. Hầu hết production chọn **Fail-Open** để tránh downtime.

### 7.3. Quy trình triển khai IPS

```
Bước 1: Deploy ở chế độ DETECTION (chỉ cảnh báo)
         │
         ▼
Bước 2: Thu thập alerts trong 2-4 tuần
         │
         ▼
Bước 3: Phân tích và TUNE rules
         ├── Tắt rules gây false positive
         ├── Tùy chỉnh threshold
         └── Whitelist traffic hợp lệ
         │
         ▼
Bước 4: Chuyển sang chế độ PREVENTION (bắt đầu chặn)
         │
         ▼
Bước 5: Tiếp tục monitor và tune
```

## 8. Snort/Suricata — IPS Rules cơ bản

```
Cú pháp Snort rule:
action protocol src_ip src_port -> dst_ip dst_port (options)
```

### Ví dụ rules:

```bash
# Phát hiện SQL Injection
alert tcp any any -> any 80 (msg:"SQL Injection Attempt"; content:"' OR '1'='1"; nocase; sid:1001; rev:1;)

# Phát hiện Port Scan (SYN scan)
alert tcp any any -> $HOME_NET any (msg:"Possible SYN Scan"; flags:S; threshold:type threshold, track by_src, count 20, seconds 10; sid:1002;)

# Chặn Shellshock exploit
drop tcp any any -> any 80 (msg:"Shellshock Attack"; content:"() {"; sid:1003;)

# Phát hiện DNS Tunneling
alert udp any any -> any 53 (msg:"Possible DNS Tunneling"; dsize:>512; sid:1004;)

# Chặn Brute Force SSH
drop tcp any any -> any 22 (msg:"SSH Brute Force"; threshold:type threshold, track by_src, count 5, seconds 60; sid:1005;)
```

**Actions:**
- `alert` — Chỉ cảnh báo (IDS mode)
- `drop` — Chặn và bỏ packet (IPS mode)
- `reject` — Chặn và gửi RST/ICMP unreachable
- `pass` — Cho phép (whitelist)

## 10. Best Practices

1. **Bắt đầu với Detection mode** — Tune trước, chặn sau
2. **Tune rules liên tục** — Giảm false positive
3. **Cập nhật signatures** — Tự động, hàng ngày
4. **High Availability** — Deploy IPS redundant (HA pair)
5. **Fail-Open cho production** — Tránh single point of failure
6. **Log và alert** — Gửi về SIEM để phân tích
7. **Performance monitoring** — Đảm bảo IPS không thành bottleneck
8. **SSL/TLS Inspection** — Giải mã HTTPS để IPS kiểm tra được
9. **Kết hợp NIPS + HIPS** — Defense in depth
10. **Regular review** — Xem lại rules, loại bỏ rules lỗi thời
