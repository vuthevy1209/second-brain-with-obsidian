
## 1. Network Segmentation là gì?

**Network Segmentation** (Phân đoạn mạng) là kỹ thuật **chia một mạng lớn thành nhiều mạng con (segment/subnet) nhỏ hơn**, mỗi segment được cách ly và kiểm soát traffic riêng biệt.

> 💡 **Ví dụ đơn giản:** Segmentation giống như **chia một tòa nhà thành nhiều phòng** với cửa khóa riêng. Nếu cháy ở phòng A, lửa không lan sang phòng B vì có **tường chống cháy** ngăn cách.

### 2.3. Lợi ích

| Lợi ích | Giải thích |
|---|---|
| **Giảm attack surface** | Attacker chỉ truy cập được segment bị xâm nhập |
| **Ngăn lateral movement** | Malware không thể lây lan tự do sang segment khác |
| **Giảm broadcast domain** | Ít broadcast → hiệu suất mạng tốt hơn |
| **Kiểm soát truy cập** | Quy định chính xác ai truy cập gì |
| **Compliance** | PCI-DSS yêu cầu tách biệt hệ thống xử lý thẻ |
| **Dễ quản lý** | Troubleshoot nhanh hơn, policy rõ ràng hơn |
| **Containment** | Sự cố bị giới hạn trong 1 segment |

## 3. Các phương pháp Segmentation

### 3.1. VLAN (Virtual LAN) — Phương pháp phổ biến nhất

#### VLAN là gì?
- Chia **1 switch vật lý** thành **nhiều mạng logic** (broadcast domain riêng)
- Thiết bị trong VLAN khác nhau **không thể giao tiếp trực tiếp** (cần router)
- Cấu hình trên **managed switch** (Layer 2/3)

#### Cấu hình VLAN trên switch (ví dụ Cisco)

```
! Tạo VLAN
vlan 10
  name Users
vlan 20
  name Servers
vlan 30
  name Management
vlan 99
  name Native

! Gán port vào VLAN (Access Port)
interface FastEthernet0/1
  switchport mode access
  switchport access vlan 10

interface FastEthernet0/10
  switchport mode access
  switchport access vlan 20

! Cấu hình Trunk Port (kết nối giữa switch hoặc đến router)
interface GigabitEthernet0/1
  switchport mode trunk
  switchport trunk allowed vlan 10,20,30
  switchport trunk native vlan 99
```

#### Inter-VLAN Routing (Router-on-a-Stick)

```
                    ┌──────────────┐
                    │   Router     │
                    │              │
                    │ Sub-int .10  │ ← 192.168.10.1 (Gateway VLAN 10)
                    │ Sub-int .20  │ ← 192.168.20.1 (Gateway VLAN 20)
                    │ Sub-int .30  │ ← 192.168.30.1 (Gateway VLAN 30)
                    └──────┬───────┘
                           │ Trunk
                    ┌──────┴───────┐
                    │   Switch     │
                    │ VLAN 10,20,30│
                    └──────────────┘
```

```
! Cấu hình Router-on-a-Stick (Cisco Router)
interface GigabitEthernet0/0.10
  encapsulation dot1Q 10
  ip address 192.168.10.1 255.255.255.0

interface GigabitEthernet0/0.20
  encapsulation dot1Q 20
  ip address 192.168.20.1 255.255.255.0

interface GigabitEthernet0/0.30
  encapsulation dot1Q 30
  ip address 192.168.30.1 255.255.255.0

! ACL kiểm soát traffic giữa VLANs
access-list 100 permit tcp 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255 eq 80
access-list 100 permit tcp 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255 eq 443
access-list 100 deny ip 192.168.10.0 0.0.0.255 192.168.30.0 0.0.0.255
access-list 100 permit ip any any
```

### 3.2. Subnet (Mạng con)

- Chia mạng dựa trên **IP addressing** (subnet mask)
- Kết hợp với **Router/L3 Switch** để kiểm soát traffic

```
Ví dụ chia subnet:
┌──────────────────────────────────────────┐
│ Network: 10.0.0.0/16                     │
│                                          │
│ ├── 10.0.1.0/24   → Users               │
│ ├── 10.0.2.0/24   → Servers             │
│ ├── 10.0.3.0/24   → Management          │
│ ├── 10.0.4.0/24   → DMZ                 │
│ ├── 10.0.5.0/24   → IoT                 │
│ └── 10.0.100.0/24 → Guest WiFi          │
└──────────────────────────────────────────┘
```

### 3.3. Physical Segmentation

- Dùng **switch/router riêng** cho từng segment
- **An toàn nhất** nhưng **đắt nhất**
- Thường dùng cho hệ thống cực kỳ nhạy cảm (quân sự, ngân hàng)

### 3.4. Micro-Segmentation (Zero Trust)

```
Traditional Segmentation:
┌────────────────────┐
│ Server Segment     │
│                    │
│ Web ← → App ← → DB│  ← Traffic tự do trong segment
│                    │
└────────────────────┘

Micro-Segmentation:
┌────────────────────┐
│ Server Segment     │
│                    │
│ Web ──?── App ──?──DB│  ← Mỗi kết nối đều được kiểm soát
│  │        │        │  │
│  🔒       🔒       🔒│  ← Policy trên từng workload
└────────────────────┘
```

- Kiểm soát traffic **giữa các workload trong cùng segment**
- Áp dụng nguyên tắc **Zero Trust** — không tin bất kỳ ai
- Thường dùng **software-defined** (VMware NSX, Cisco ACI)
- **Ví dụ:** Web server chỉ được nói chuyện với App server trên port 8080, App server chỉ được nói chuyện với DB trên port 1433

## 4. Segmentation trên Windows Server

### 4.1. Windows Server Hyper-V Virtual Switch

```powershell
# Tạo Internal Virtual Switch (segment riêng cho VMs)
New-VMSwitch -Name "Server-Segment" -SwitchType Internal
New-VMSwitch -Name "DMZ-Segment" -SwitchType Internal
New-VMSwitch -Name "Management-Segment" -SwitchType Private

# Gán VM vào segment
Connect-VMNetworkAdapter -VMName "WebServer" -SwitchName "DMZ-Segment"
Connect-VMNetworkAdapter -VMName "DBServer" -SwitchName "Server-Segment"

# Cấu hình IP cho Virtual Switch adapter (trên host)
New-NetIPAddress -InterfaceAlias "vEthernet (Server-Segment)" `
    -IPAddress 192.168.20.1 -PrefixLength 24
New-NetIPAddress -InterfaceAlias "vEthernet (DMZ-Segment)" `
    -IPAddress 172.16.0.1 -PrefixLength 24
```

**Loại Virtual Switch:**

| Loại | Mô tả |
|---|---|
| **External** | Kết nối VM ra mạng vật lý (qua NIC vật lý) |
| **Internal** | VM ↔ Host communication (không ra ngoài) |
| **Private** | Chỉ VM ↔ VM (hoàn toàn cách ly) |

### 4.2. VLAN trên Hyper-V

```powershell
# Gán VLAN ID cho VM network adapter
Set-VMNetworkAdapterVlan -VMName "WebServer" -Access -VlanId 10
Set-VMNetworkAdapterVlan -VMName "DBServer" -Access -VlanId 20
Set-VMNetworkAdapterVlan -VMName "AdminPC" -Access -VlanId 30

# Cấu hình Trunk cho VM (nhận nhiều VLAN)
Set-VMNetworkAdapterVlan -VMName "Router-VM" -Trunk -AllowedVlanIdList "10,20,30" -NativeVlanId 1

# Xem VLAN config
Get-VMNetworkAdapterVlan -VMName "WebServer"
```

### 4.3. Windows Firewall — Kiểm soát traffic giữa segments

```powershell
# Chặn traffic từ User segment đến Management segment
New-NetFirewallRule -DisplayName "Block Users to Management" `
    -Direction Inbound `
    -RemoteAddress 192.168.10.0/24 `
    -LocalAddress 192.168.30.0/24 `
    -Action Block

# Cho phép Users truy cập Web Server (HTTP/HTTPS)
New-NetFirewallRule -DisplayName "Allow Users to Web" `
    -Direction Inbound `
    -Protocol TCP `
    -LocalPort 80,443 `
    -RemoteAddress 192.168.10.0/24 `
    -Action Allow

# Cho phép Management truy cập tất cả (RDP)
New-NetFirewallRule -DisplayName "Allow Management RDP" `
    -Direction Inbound `
    -Protocol TCP `
    -LocalPort 3389 `
    -RemoteAddress 192.168.30.0/24 `
    -Action Allow

# Chặn IoT segment truy cập mọi thứ (trừ Internet)
New-NetFirewallRule -DisplayName "Block IoT to Internal" `
    -Direction Inbound `
    -RemoteAddress 192.168.50.0/24 `
    -LocalAddress 192.168.0.0/16 `
    -Action Block
```

### 4.4. IPsec Connection Security Rules (Micro-Segmentation)

```powershell
# Yêu cầu xác thực giữa 2 server segments
New-NetIPsecRule -DisplayName "Require Auth Server-to-Server" `
    -InboundSecurity Require `
    -OutboundSecurity Require `
    -LocalAddress 192.168.20.0/24 `
    -RemoteAddress 192.168.20.0/24

# Cấu hình certificate-based authentication
$certProp = New-NetIPsecAuthProposal -Machine -Cert `
    -Authority "CN=Company-CA" -AuthorityType Root
$authSet = New-NetIPsecPhase1AuthSet -DisplayName "Server Auth" `
    -Proposal $certProp

New-NetIPsecRule -DisplayName "Encrypt Server Traffic" `
    -Phase1AuthSet $authSet.Name `
    -InboundSecurity Require `
    -OutboundSecurity Require
```

### 4.5. Network Access Protection (NAP) / Network Policy Server (NPS)

```
NAP kiểm tra "health" của máy trước khi cho vào segment:
├── Máy có cập nhật Windows Update?
├── Antivirus có chạy và up-to-date?
├── Firewall có bật?
└── Nếu KHÔNG → Đưa vào "Remediation Network" (segment cách ly)
```

| Source ↓ / Dest → | DMZ | Users | Servers | DB | Mgmt | Guest |
|---|---|---|---|---|---|---|
| **DMZ** | ✅ | ❌ | ❌ (trừ API) | ❌ (trừ SQL) | ❌ | ❌ |
| **Users** | ✅ (HTTP) | ✅ | ✅ (HTTP/SMB) | ❌ | ❌ | ❌ |
| **Servers** | ❌ | ❌ | ✅ | ✅ (SQL) | ❌ | ❌ |
| **DB** | ❌ | ❌ | ❌ | ✅ | ❌ | ❌ |
| **Mgmt** | ✅ (all) | ✅ (all) | ✅ (all) | ✅ (all) | ✅ | ✅ |
| **Guest** | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ (Internet only) |

## 6. Kiểm tra và giám sát Segmentation

```powershell
# Kiểm tra routing table
Get-NetRoute | Format-Table DestinationPrefix, NextHop, InterfaceAlias

# Kiểm tra kết nối giữa segments
Test-NetConnection -ComputerName 192.168.20.10 -Port 1433

# Trace route giữa segments
Test-NetConnection -ComputerName 192.168.20.10 -TraceRoute

# Xem traffic bị chặn bởi Firewall
Get-WinEvent -LogName "Microsoft-Windows-Windows Firewall With Advanced Security/Firewall" -MaxEvents 50

# Monitor traffic trên interface
Get-NetAdapterStatistics | Format-Table Name, ReceivedBytes, SentBytes

# Kiểm tra VLAN configuration
Get-VMNetworkAdapterVlan | Format-Table VMName, AccessVlanId, OperationMode
```

## 7. Compliance và Segmentation

### PCI-DSS (Payment Card Industry)

```
Yêu cầu PCI-DSS liên quan đến Segmentation:
├── Requirement 1: Cài đặt và duy trì firewall
├── Requirement 2: Không dùng default password
│
├── ⭐ Network segmentation KHÔNG BẮT BUỘC
│   NHƯNG nếu không segment → TOÀN BỘ mạng thuộc phạm vi PCI audit
│
└── Nếu segment đúng cách:
    ├── Chỉ Cardholder Data Environment (CDE) thuộc scope audit
    ├── Giảm chi phí audit đáng kể
    └── Giảm rủi ro
```

### Tiêu chuẩn khác

| Standard | Yêu cầu Segmentation |
|---|---|
| **HIPAA** | Khuyến nghị tách biệt hệ thống chứa PHI (Protected Health Information) |
| **NIST 800-171** | Yêu cầu kiểm soát boundary giữa các hệ thống |
| **ISO 27001** | A.13 — Network security management |
| **SOX** | Kiểm soát truy cập hệ thống tài chính |

## 8. Zero Trust và Micro-Segmentation

### 8.1. Nguyên tắc Zero Trust

```
Traditional (Castle-and-Moat):
"Bên trong firewall = tin tưởng"          ← ❌ Sai lầm

Zero Trust:
"Không tin ai, verify everything"         ← ✅ Đúng
├── Verify Identity (xác minh danh tính)
├── Verify Device (kiểm tra thiết bị)
├── Least Privilege (quyền tối thiểu)
├── Assume Breach (giả sử đã bị hack)
└── Monitor Everything (giám sát mọi thứ)
```

### 8.2. Áp dụng Zero Trust trên Windows

```powershell
# 1. Windows Defender Credential Guard (bảo vệ credentials)
# Bật qua Group Policy:
# Computer Config → Admin Templates → System → Device Guard
# → Turn On Virtualization Based Security → Enabled

# 2. Windows Hello for Business (passwordless auth)
# Cấu hình qua Group Policy hoặc Intune

# 3. Conditional Access (Azure AD)
# Kiểm tra: Device compliance, Location, Risk level trước khi cho truy cập

# 4. Just-In-Time (JIT) Admin Access
# Chỉ cấp quyền admin khi cần, tự thu hồi sau thời gian
```

## 9. Best Practices

1. **Bắt đầu với Traffic Analysis** — Hiểu traffic pattern trước khi segment
2. **Principle of Least Privilege** — Chỉ cho phép traffic cần thiết giữa segments
3. **Document everything** — Vẽ sơ đồ mạng, ghi chú traffic matrix
4. **VLAN + Firewall** — VLAN chia mạng, Firewall kiểm soát traffic
5. **Quản lý riêng** — Management segment riêng cho admin (out-of-band management)
6. **Guest WiFi cách ly** — Guest network tách hoàn toàn khỏi production
7. **IoT cách ly** — IoT devices trong segment riêng (camera, sensor...)
8. **Monitor cross-segment traffic** — Giám sát traffic giữa các segment
9. **Regular review** — Kiểm tra segmentation rules định kỳ
10. **Test segmentation** — Dùng penetration testing để verify
11. **Hướng tới Zero Trust** — Micro-segmentation là tương lai
