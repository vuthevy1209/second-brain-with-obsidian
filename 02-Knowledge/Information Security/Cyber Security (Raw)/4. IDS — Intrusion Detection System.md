# IDS — Intrusion Detection System (Phát hiện tấn công)

## 1. IDS là gì?

**IDS (Intrusion Detection System)** là hệ thống **giám sát và phát hiện** các hoạt động đáng ngờ hoặc tấn công trên mạng/hệ thống. IDS **CHỈ CẢNH BÁO** (alert), **KHÔNG TỰ ĐỘNG CHẶN** traffic.

> 💡 **Ví dụ đơn giản:** IDS giống như camera an ninh — phát hiện kẻ trộm và báo động, nhưng **không tự khóa cửa** hay bắt kẻ trộm. Việc xử lý do con người hoặc hệ thống khác (IPS) thực hiện.

#### Nó có thể được triển khai dưới nhiều dạng:

- Thiết bị phần cứng (appliance): Ví dụ một hộp chuyên dụng của Cisco, Fortinet, Palo Alto… cắm vào mạng để giám sát traffic.
- Phần mềm chạy trên server/VM: Ví dụ Snort, Suricata, Zeek.
- Dịch vụ cloud: IDS của AWS, Azure, GCP.
---

## 2. Tại sao cần IDS?

| Mục đích | Giải thích |
|---|---|
| **Phát hiện tấn công** | Nhận diện các cuộc tấn công đang diễn ra |
| **Cảnh báo sớm** | Thông báo cho admin trước khi thiệt hại xảy ra |
| **Phân tích forensic** | Cung cấp log chi tiết để điều tra sự cố |
| **Compliance** | Đáp ứng yêu cầu bảo mật của các tiêu chuẩn (PCI-DSS, HIPAA...) |
| **Phát hiện bất thường** | Nhận ra hành vi bất thường mà Firewall không chặn được |

## 3. Phân loại IDS

### 3.1. Theo vị trí triển khai

#### a) NIDS — Network-based IDS

![[4. IDS — Intrusion Detection System-1785942240217.webp]]
- NIDS không nằm inline với luồng traffic.
- Nó nhận bản sao gói tin từ switch (SPAN/Mirror port hoặc TAP).
- Nó phân tích rồi cảnh báo.


- <mark style="background:#b1ffff">Đặt tại **điểm chiến lược** trên mạng (thường sau Firewall)</mark>
- Giám sát **toàn bộ traffic** đi qua network segment
- Sử dụng **port mirroring (SPAN)** hoặc **network TAP** để copy traffic
- <mark style="background:#affad1">**Ưu điểm:** Giám sát nhiều host cùng lúc, không ảnh hưởng hiệu suất host</mark>
- <mark style="background:rgba(5, 117, 197, 0.2)">**Nhược điểm:** Không thấy traffic mã hóa (HTTPS), có thể bỏ sót khi traffic lớn</mark>

#### b) HIDS — Host-based IDS

```
┌─────────────────────────────┐
│         Server A            │
│                             │
│  ┌───────────────────────┐  │
│  │       HIDS Agent      │  │  ◄── Cài trên từng host
│  │                       │  │
│  │ • Monitor log files   │  │
│  │ • Monitor file system │  │
│  │ • Monitor processes   │  │
│  │ • Monitor registry    │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

- Cài đặt **trực tiếp trên từng host** (server/workstation)
- Giám sát:
  - **System logs** (Event Log trên Windows)
  - **File integrity** (file có bị thay đổi không?)
  - **Process activity** (tiến trình đáng ngờ)
  - **Registry changes** (trên Windows)
  - **User activity** (đăng nhập bất thường)
- **Ưu điểm:** Phân tích sâu, thấy được traffic mã hóa (sau khi giải mã)
- **Nhược điểm:** Cần cài trên từng host, tốn tài nguyên host

### 3.2. Theo phương pháp phát hiện

#### a) Signature-based Detection (Phát hiện dựa trên chữ ký)

```
Traffic đến → So sánh với database chữ ký → Match? → ALERT!
```

- So sánh traffic/hành vi với **database các mẫu tấn công đã biết** (signatures)
- Giống như **antivirus** — quét theo mẫu
- **Ưu điểm:**
  - Chính xác cao với **tấn công đã biết**
  - Ít false positive
  - Nhanh
- **Nhược điểm:**
  - **Không phát hiện được tấn công mới** (zero-day)
  - Cần cập nhật signature database thường xuyên

```
Ví dụ Signature:
alert tcp any any -> any 80 (content:"../../../etc/passwd"; msg:"Directory Traversal Attack"; sid:1001;)
```

#### b) Anomaly-based Detection (Phát hiện dựa trên bất thường)

```
Học baseline "bình thường" → So sánh traffic hiện tại → Bất thường? → ALERT!
```

- Xây dựng **baseline** (mô hình hoạt động bình thường)
- Phát hiện **hành vi lệch khỏi baseline**
- **Ưu điểm:**
  - Phát hiện được **tấn công mới** (zero-day)
  - Phát hiện insider threat
- **Nhược điểm:**
  - **Nhiều false positive** (cảnh báo giả)
  - Cần thời gian training baseline
  - Phức tạp

```
Ví dụ:
Baseline: Server web trung bình 100 requests/phút
Hiện tại: Đột nhiên 10,000 requests/phút → ANOMALY → Có thể DDoS
```

#### c) Heuristic / Behavioral Detection

- Kết hợp signature + anomaly
- Phân tích **hành vi** (behavior) thay vì chỉ pattern
- Sử dụng **machine learning** và AI

## 4. Kiến trúc IDS

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   Sensor    │───►│  Analyzer   │───►│   Console   │
│  (Thu thập) │    │ (Phân tích) │    │  (Hiển thị) │
└─────────────┘    └─────────────┘    └──────┬──────┘
                                             │
                                      ┌──────┴──────┐
                                      │   Alert     │
                                      │  Database   │
                                      └─────────────┘
```

| Thành phần | Chức năng |
|---|---|
| **Sensor** | Thu thập dữ liệu (packet capture, log collection) |
| **Analyzer/Engine** | Phân tích dữ liệu, so sánh với rules/signatures |
| **Console/Dashboard** | Giao diện quản lý, hiển thị cảnh báo |
| **Alert Database** | Lưu trữ cảnh báo và log |

## 5. IDS trên Windows Server

### 5.1. Windows Event Log — HIDS cơ bản

Windows Server có sẵn cơ chế giám sát:

```
Event Viewer (eventvwr.msc)
├── Windows Logs
│   ├── Application    → Log ứng dụng
│   ├── Security       → Login/logout, access, audit ← QUAN TRỌNG NHẤT
│   ├── System         → Service start/stop, driver errors
│   ├── Setup          → Windows Update, driver install
│   └── Forwarded Events → Events từ máy khác
└── Applications and Services Logs
    └── Microsoft → Windows → nhiều service logs
```

### 5.2. Cấu hình Audit Policy (Security Log)

```
Audit Policy (secpol.msc hoặc GPO):
├── Account Logon Events    → Xác thực (Kerberos, NTLM)
├── Account Management      → Tạo/xóa/sửa user/group
├── Directory Service Access → Thay đổi Active Directory
├── Logon Events           → Đăng nhập/đăng xuất
├── Object Access          → Truy cập file/folder/registry
├── Policy Change          → Thay đổi security policy
├── Privilege Use          → Sử dụng quyền đặc biệt
├── Process Tracking       → Tạo/kết thúc process
└── System Events          → Khởi động/tắt máy, system events
```

```powershell
# Cấu hình Advanced Audit Policy qua PowerShell
auditpol /set /subcategory:"Logon" /success:enable /failure:enable
auditpol /set /subcategory:"Account Lockout" /success:enable /failure:enable
auditpol /set /subcategory:"File System" /success:enable /failure:enable

# Xem cấu hình audit hiện tại
auditpol /get /category:*

# Xem Security Event Log
Get-EventLog -LogName Security -Newest 50 | Format-Table TimeGenerated, EventID, Message -AutoSize

# Tìm failed login attempts (Event ID 4625)
Get-EventLog -LogName Security -InstanceId 4625 -Newest 20

# Tìm successful login (Event ID 4624)
Get-EventLog -LogName Security -InstanceId 4624 -Newest 20

# Event IDs quan trọng:
# 4624 - Successful Logon
# 4625 - Failed Logon
# 4648 - Logon with Explicit Credentials
# 4720 - User Account Created
# 4726 - User Account Deleted
# 4732 - Member Added to Security Group
# 4740 - Account Locked Out
# 1102 - Audit Log Cleared (⚠️ Đáng ngờ!)
```

### 5.3. Windows Event Forwarding (WEF)

- Thu thập logs từ **nhiều máy** về **1 server trung tâm**
- Tạo **SIEM-like** capability trên Windows

```powershell
# Trên Collector (server thu thập):
wecutil qc  # Quick config

# Trên Source (máy gửi log):
winrm quickconfig

# Tạo subscription qua Event Viewer → Subscriptions
```

### 5.4. Phần mềm IDS phổ biến

| Phần mềm | Loại | Miễn phí | Mô tả |
|---|---|---|---|
| **Snort** | NIDS | ✅ | Open source, rule-based, phổ biến nhất |
| **Suricata** | NIDS | ✅ | Multi-threaded, hỗ trợ Snort rules |

## 6. Sysmon — HIDS nâng cao cho Windows

### 6.1. Sysmon là gì?
- Tool miễn phí từ **Microsoft Sysinternals**
- Ghi log chi tiết hơn Windows Event Log mặc định
- Rất hữu ích cho **threat hunting** và **incident response**

### 6.2. Sysmon ghi log những gì?

| Event ID | Mô tả |
|---|---|
| **1** | Process Creation (tạo tiến trình) — gồm cả command line |
| **2** | File Creation Time Changed |
| **3** | Network Connection |
| **5** | Process Terminated |
| **6** | Driver Loaded |
| **7** | Image Loaded (DLL) |
| **8** | CreateRemoteThread (injection!) |
| **10** | Process Access (LSASS access = credential theft!) |
| **11** | File Created |
| **12-14** | Registry Events |
| **15** | File Stream Created (ADS) |
| **22** | DNS Query |

### 6.3. Cài đặt và cấu hình Sysmon

```cmd
:: Tải Sysmon từ Sysinternals
:: Cài đặt với cấu hình mặc định
sysmon -i -accepteula

:: Cài đặt với file cấu hình tùy chỉnh
sysmon -i sysmonconfig.xml -accepteula

:: Cập nhật cấu hình
sysmon -c sysmonconfig.xml

:: Xem log: Event Viewer → Applications and Services Logs → Microsoft → Windows → Sysmon
```

## 7. Chỉ số đánh giá IDS

| Chỉ số | Mô tả | Tốt khi |
|---|---|---|
| **True Positive (TP)** | Phát hiện đúng tấn công thật | Càng nhiều càng tốt |
| **True Negative (TN)** | Nhận đúng traffic bình thường | Càng nhiều càng tốt |
| **False Positive (FP)** | Cảnh báo giả (traffic bình thường bị báo là tấn công) | Càng ít càng tốt |
| **False Negative (FN)** | Bỏ sót (tấn công thật nhưng không phát hiện) | Càng ít càng tốt |

> ⚠️ **False Positive** gây "alert fatigue" — quá nhiều cảnh báo giả khiến admin bỏ qua cảnh báo thật.
>
> ⚠️ **False Negative** nguy hiểm nhất — tấn công xảy ra mà không ai biết.

## 8. IDS Evasion Techniques (Kỹ thuật né IDS)

Hiểu cách attacker né IDS để biết cách phòng thủ:

| Kỹ thuật | Mô tả |
|---|---|
| **Fragmentation** | Chia packet thành mảnh nhỏ để IDS không ghép lại được |
| **Encryption** | Mã hóa traffic → IDS không đọc được payload |
| **Encoding** | URL encoding, Base64, Unicode để bypass signature |
| **Slow Attack** | Tấn công rất chậm để dưới ngưỡng phát hiện |
| **Polymorphic Attack** | Thay đổi mã tấn công liên tục để không match signature |
| **Protocol Abuse** | Lợi dụng giao thức hợp lệ (DNS tunneling, ICMP tunneling) |

## 9. Best Practices

1. **Đặt sensor đúng vị trí** — Sau Firewall, trước server farm
2. **Kết hợp NIDS + HIDS** — Giám sát cả network và host level
3. **Cập nhật signatures thường xuyên** — Mới nhất có thể
4. **Tune rules** — Giảm false positive bằng cách tùy chỉnh rules cho môi trường
5. **Centralize logs** — Gửi tất cả alerts về SIEM trung tâm
6. **Incident Response Plan** — Có quy trình xử lý khi nhận được alert
7. **Bật Audit Policy đầy đủ** — Trên Windows Server
8. **Cài Sysmon** — Trên tất cả Windows Server quan trọng
9. **Monitor the monitor** — Đảm bảo IDS chính nó đang hoạt động
