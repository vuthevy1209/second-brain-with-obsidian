# A09: Security Logging and Monitoring Failures (Lỗi ghi log và giám sát bảo mật)

## 1. Khái niệm
Lỗi này xảy ra khi hệ thống không ghi nhận log, ghi log quá ít (thiếu thông tin), hoặc không có cơ chế cảnh báo (Alert) khi có các hành vi đáng ngờ. Kết quả là kẻ tấn công có thể rà quét, phá hoại hệ thống trong nhiều tháng mà quản trị viên không hề hay biết.

## 2. Ví dụ lỗi (Vulnerable Practices)

- **Không ghi log đăng nhập thất bại:** Kẻ tấn công Brute-force mật khẩu hàng triệu lần, nhưng server không lưu log nào, team Security không thể điều tra.
- **Bắt Exception nhưng im lặng:**
```java
public void processPayment() {
    try {
        // ...
    } catch (Exception e) {
        // LỖ HỔNG: Bắt lỗi nhưng không ghi log (Swallowed Exception). 
        // Khi lỗi logic hoặc hacker tấn công gây lỗi, hệ thống bị mù màu hoàn toàn.
    }
}
```
- **Ghi log dữ liệu nhạy cảm (Data Leakage qua Log):**
```java
// LỖ HỔNG: Ghi log cả thẻ tín dụng và mật khẩu vào file log (bản rõ).
logger.info("Người dùng " + user.getName() + " đăng nhập với mật khẩu: " + user.getPassword());
```

## 3. Cách ghi log an toàn (Secure Logging)

Sử dụng thư viện phổ biến như `SLF4J` kết hợp `Logback` hoặc `Log4j2` (phiên bản đã vá) trong Spring Boot.

### 3.1. Ghi đầy đủ thông tin bảo mật quan trọng
Mọi sự kiện liên quan đến xác thực, phân quyền (đăng nhập đúng/sai, thay đổi mật khẩu, truy cập bị từ chối) ĐỀU PHẢI được ghi log.

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;

@Service
public class AuthenticationService {
    
    private static final Logger logger = LoggerFactory.getLogger(AuthenticationService.class);

    public void authenticate(String username, String password) {
        try {
            // Logic kiểm tra DB
            boolean isValid = checkInDb(username, password);
            if (!isValid) {
                // CODE AN TOÀN: Ghi log sự kiện thất bại (không lưu password)
                logger.warn("Security Event - Đăng nhập THẤT BẠI từ username: {}", username);
                throw new BadCredentialsException("Sai tài khoản");
            }
            
            // CODE AN TOÀN: Ghi log thành công
            logger.info("Security Event - Đăng nhập THÀNH CÔNG cho username: {}", username);
            
        } catch (Exception e) {
            // CODE AN TOÀN: Ghi nhận Exception đầy đủ
            logger.error("Security Event - Lỗi hệ thống trong quá trình xác thực", e);
        }
    }
}
```

### 3.2. Che giấu dữ liệu nhạy cảm (Data Masking)
Không bao giờ được in thẻ tín dụng hay số tài khoản đầy đủ ra log.

```java
public String maskCreditCard(String creditCard) {
    if (creditCard == null || creditCard.length() < 4) return "";
    // Chỉ hiển thị 4 số cuối
    return "XXXX-XXXX-XXXX-" + creditCard.substring(creditCard.length() - 4);
}

public void processPayment(String creditCardNumber) {
    // CODE AN TOÀN: Che mờ dữ liệu trước khi log
    logger.info("Đang xử lý thanh toán cho thẻ: {}", maskCreditCard(creditCardNumber));
}
```

## 4. Cách phòng chống khác (Hệ thống)
- Chuyển log ra khỏi server ứng dụng (Forward logs). Đưa về hệ thống quản lý log tập trung **SIEM** như ElasticSearch, Splunk, Datadog.
- Xây dựng hệ thống tự động sinh **Cảnh báo (Alerting)**. Ví dụ: Nếu có 50 log đăng nhập thất bại từ 1 IP trong vòng 1 phút, tự động bắn thông báo qua Slack/Email cho đội Security.
- Đảm bảo file log không thể bị thay đổi hoặc xóa bởi tài khoản ứng dụng (Log Integrity).
