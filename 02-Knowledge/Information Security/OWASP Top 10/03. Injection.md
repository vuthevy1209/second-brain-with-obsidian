# A03: Injection (Lỗ hổng tiêm nhiễm)

## 1. Khái niệm
Injection (Tiêm nhiễm) xảy ra khi dữ liệu đầu vào từ người dùng (như form, URL, tham số API) không được kiểm duyệt và làm sạch (sanitize) chặt chẽ, lọt vào trình thông dịch (như cơ sở dữ liệu, OS shell, LDAP) dưới dạng "lệnh thực thi". Kẻ tấn công có thể chèn mã độc để thay đổi logic ban đầu của ứng dụng.

Phổ biến nhất là **SQL Injection (SQLi)**.

## 2. Code ví dụ lỗ hổng (Vulnerable Code)

Dưới đây là ví dụ mã Java sử dụng `java.sql.Statement` nối chuỗi trực tiếp (String concatenation) để tạo câu lệnh SQL:

```java
import java.sql.Connection;
import java.sql.ResultSet;
import java.sql.Statement;

public class VulnerableDao {
    
    public void searchUser(Connection connection, String searchName) {
        try {
            // LỖ HỔNG: Nối chuỗi trực tiếp dữ liệu do người dùng cung cấp vào lệnh SQL
            String query = "SELECT * FROM users WHERE username = '" + searchName + "'";
            
            Statement statement = connection.createStatement();
            ResultSet resultSet = statement.executeQuery(query);
            
            // Xử lý kết quả...
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
// Kẻ tấn công nhập searchName là: ' OR '1'='1
// Câu SQL sẽ trở thành: SELECT * FROM users WHERE username = '' OR '1'='1'
// Kết quả là trả về TOÀN BỘ database thay vì chỉ tìm user.
```

## 3. Code an toàn (Secure Code)

Cách an toàn nhất để phòng tránh SQL Injection là sử dụng **Prepared Statements** (Truy vấn có tham số hóa). Trình điều khiển cơ sở dữ liệu sẽ tách biệt phần "Lệnh SQL" và phần "Dữ liệu" của người dùng.

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;

public class SecureDao {
    
    public void searchUser(Connection connection, String searchName) {
        try {
            // CODE AN TOÀN: Sử dụng dấu ? làm tham số (Parameterized Query)
            String query = "SELECT * FROM users WHERE username = ?";
            
            PreparedStatement pstmt = connection.prepareStatement(query);
            
            // Set giá trị cho tham số. Trình điều khiển JDBC sẽ tự động
            // escape (làm sạch) các ký tự đặc biệt như dấu nháy đơn (').
            pstmt.setString(1, searchName); 
            
            ResultSet resultSet = pstmt.executeQuery();
            
            // Xử lý kết quả...
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

### Nếu sử dụng JPA / Hibernate (Spring Data JPA)

```java
public interface UserRepository extends JpaRepository<User, Long> {
    
    // An toàn mặc định: Spring Data JPA tự động sử dụng Prepared Statements
    List<User> findByUsername(String username);
    
    // AN TOÀN khi dùng @Query
    @Query("SELECT u FROM User u WHERE u.username = :username")
    List<User> searchByUsernameSecure(@Param("username") String username);
    
    // LỖ HỔNG NGUY HIỂM: Nối chuỗi trong Custom Query nếu cố tình viết sai
    // (Không bao giờ được dùng cách này)
    // @Query("SELECT u FROM User u WHERE u.username = " + username)
}
```

## 4. Cách phòng chống khác
- **Sử dụng Object Relational Mapping (ORM):** Hầu hết các ORM (như Hibernate/JPA) đã mặc định dùng parameterized queries.
- **Validation chặt chẽ (Whitelist):** Luôn xác thực đầu vào từ người dùng xem có đúng định dạng mong muốn (ví dụ: tuổi phải là số, email phải có định dạng email) trước khi đưa vào bất kỳ xử lý nào.
- Tránh dùng OS Command Injection bằng cách không chạy trực tiếp `Runtime.getRuntime().exec()` với chuỗi nối đầu vào từ user. Sử dụng `ProcessBuilder` và truyền tham số an toàn.
