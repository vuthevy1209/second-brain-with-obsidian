# A07: Identification and Authentication Failures (Lỗi xác thực và định danh)

## 1. Khái niệm
Lỗi này xảy ra khi các chức năng liên quan đến định danh người dùng (đăng nhập, quên mật khẩu, phiên làm việc) không được thực thi chặt chẽ. Kẻ tấn công có thể giả mạo danh tính của người dùng hợp lệ, thực hiện Brute-force mật khẩu hoặc đánh cắp Session (phiên làm việc).

## 2. Các ví dụ về lỗi (Vulnerable Practices)

- **Không giới hạn số lần đăng nhập sai:** Kẻ tấn công dùng tool tự động (như Burp Suite Intruder) ném hàng triệu mật khẩu vào API `/login` cho đến khi trúng.
- **Session không bao giờ hết hạn:** Người dùng đăng nhập từ máy tính công cộng, dù đã tắt trình duyệt nhưng Session/Cookie vẫn còn sống nhiều ngày sau.
- **Để lộ Session ID trên URL (URL Rewriting):** `http://example.com/home;jsessionid=ABC12345`

## 3. Khắc phục bằng Java (Spring Security)

### 3.1. Chống Brute Force (Giới hạn đăng nhập sai)
Mặc định Spring Security không giới hạn số lần đăng nhập. Chúng ta cần tự xây dựng cơ chế đếm số lần sai và khóa tài khoản (Account Lockout).

```java
@Service
public class LoginAttemptService {

    private final int MAX_ATTEMPT = 5;
    // Dùng Map hoặc Redis để lưu IP hoặc Username đang cố gắng login
    private LoadingCache<String, Integer> attemptsCache;

    public LoginAttemptService() {
        super();
        // Cấu hình Cache sẽ tự reset sau 15 phút
        attemptsCache = CacheBuilder.newBuilder().expireAfterWrite(15, TimeUnit.MINUTES)
                .build(new CacheLoader<String, Integer>() {
                    public Integer load(String key) {
                        return 0;
                    }
                });
    }

    public void loginSucceeded(String key) {
        attemptsCache.invalidate(key); // Xóa bộ đếm nếu thành công
    }

    public void loginFailed(String key) {
        int attempts = 0;
        try {
            attempts = attemptsCache.get(key);
        } catch (ExecutionException e) {
            attempts = 0;
        }
        attempts++;
        attemptsCache.put(key, attempts);
    }

    public boolean isBlocked(String key) {
        try {
            // CODE AN TOÀN: Nếu sai quá 5 lần -> Chặn (Lock)
            return attemptsCache.get(key) >= MAX_ATTEMPT;
        } catch (ExecutionException e) {
            return false;
        }
    }
}
```

### 3.2. Quản lý Session an toàn
Trong Spring Security (class kế thừa `WebSecurityConfigurerAdapter` hoặc cấu hình `SecurityFilterChain`), chúng ta cần cấu hình quản lý session:

```java
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        // ...
        .sessionManagement(session -> session
            // CODE AN TOÀN: Ngăn không cho 1 user login ở quá nhiều thiết bị cùng lúc
            .maximumSessions(1)
            .maxSessionsPreventsLogin(false) // Nếu login máy mới, đẩy máy cũ ra
        )
        .sessionManagement(session -> session
            // CODE AN TOÀN: Fix lỗi Session Fixation (tạo Session ID mới khi đăng nhập thành công)
            .sessionFixation().migrateSession() 
        );
        
    return http.build();
}
```

## 4. Cách phòng chống khác
- **Xác thực đa yếu tố (MFA):** Luôn yêu cầu OTP qua điện thoại hoặc ứng dụng Authenticator bên cạnh mật khẩu.
- Thiết lập thời gian sống (TTL - Time to live) của Session và JWT ngắn lại (ví dụ 15-30 phút), dùng Refresh Token thay vì cấp JWT dài hạn.
- Đặt các cờ bảo mật cho Session Cookie như `HttpOnly` (chống XSS lấy cookie), `Secure` (chỉ gửi qua HTTPS) và `SameSite=Strict`.
