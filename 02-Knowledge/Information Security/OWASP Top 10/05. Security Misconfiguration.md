# A05: Security Misconfiguration (Cấu hình bảo mật sai)

## 1. Khái niệm
Security Misconfiguration xảy ra khi các thiết lập an ninh của framework, hệ điều hành, web server, hoặc database không được cấu hình đúng cách, để nguyên giá trị mặc định thiếu an toàn, hoặc để lộ quá nhiều thông tin chi tiết trên môi trường Production.

## 2. Ví dụ cấu hình lỗi (Vulnerable Configuration)

Trong hệ sinh thái **Spring Boot**, việc quên tắt các tính năng debug hoặc lộ lọt thông báo lỗi hệ thống là rất phổ biến.

**Ví dụ 1: application.properties trên Production bị để hớ hênh**
```properties
# LỖ HỔNG: Kích hoạt H2 console trên môi trường thực tế 
# (Kẻ tấn công có thể truy cập /h2-console để tương tác với Database)
spring.h2.console.enabled=true
spring.h2.console.path=/h2-console

# LỖ HỔNG: Hiển thị toàn bộ Stack Trace ra ngoài khi có lỗi (Exception)
# Lộ lọt tên file, thư viện, version đang dùng, đường dẫn trên server
server.error.include-stacktrace=always
```

**Ví dụ 2: Lỗi xử lý Exception trong Controller (Java)**
```java
@GetMapping("/user/{id}")
public User getUser(@PathVariable String id) {
    // Nếu user nhập chuỗi "abc" vào thuộc tính Long, hệ thống sẽ ném ra 
    // NumberFormatException và in toàn bộ stack trace ra client do cấu hình sai.
    Long userId = Long.parseLong(id); 
    return userService.findById(userId);
}
```

## 3. Cấu hình an toàn (Secure Configuration)

### 3.1. Cấu hình Properties an toàn
Trên môi trường Production, phải tắt H2 Console và ẩn hoàn toàn stack trace với End-user:
```properties
# CODE AN TOÀN: Tắt các tính năng debug, ẩn chi tiết lỗi
spring.h2.console.enabled=false
server.error.include-stacktrace=never
server.error.include-message=never
```

### 3.2. Quản lý Lỗi tập trung (Global Exception Handler)
Thay vì để Spring tự văng lỗi trả về Tomcat Error Page, hãy sử dụng `@ControllerAdvice` để hứng mọi exception và trả về thông báo chung chung cho người dùng (ẩn đi chi tiết nhạy cảm), đồng thời ghi log lại cho developer xem.

```java
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.bind.annotation.ExceptionHandler;

@ControllerAdvice
public class GlobalExceptionHandler {

    // CODE AN TOÀN: Bắt mọi Exception không xác định
    @ExceptionHandler(Exception.class)
    public ResponseEntity<String> handleAllExceptions(Exception ex) {
        // Ghi chi tiết lỗi vào hệ thống log (dành cho quản trị viên/developer)
        // logger.error("Lỗi hệ thống: ", ex);
        
        // Trả về cho End-user một thông báo chung chung, lịch sự, 
        // KHÔNG hiển thị cấu trúc code hay chi tiết stack trace.
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                             .body("Đã xảy ra lỗi trong quá trình xử lý. Vui lòng liên hệ Admin.");
    }
}
```

## 4. Cách phòng chống khác
- Thực hiện **Hardening** máy chủ: Tắt toàn bộ các port, service không sử dụng.
- Đổi toàn bộ password mặc định (như `admin/admin` của Tomcat, RabbitMQ, MongoDB...).
- Triển khai **Security Headers** như `X-Frame-Options`, `Content-Security-Policy` trong Spring Security để chống Clickjacking và XSS phần nào.
- Thường xuyên quét bằng các công cụ dò quét lỗ hổng cấu hình (như Nessus, OpenVAS).
