# A01: Broken Access Control (Lỗi kiểm soát truy cập)

## 1. Khái niệm
Broken Access Control (Lỗi kiểm soát truy cập) xảy ra khi ứng dụng không kiểm tra hoặc kiểm tra không đầy đủ quyền hạn của người dùng trước khi cho phép họ truy cập tài nguyên hoặc thực hiện hành động. 
Hậu quả là người dùng (hoặc kẻ tấn công) có thể truy cập, sửa đổi hoặc xóa dữ liệu của người khác, hoặc thậm chí chiếm quyền quản trị.

Lỗi phổ biến nhất trong nhóm này là **IDOR** (Insecure Direct Object Reference).

## 2. Code ví dụ lỗ hổng (Vulnerable Code)

Dưới đây là một ví dụ bằng `Java` (Spring Boot) bị lỗi IDOR:

```java
@RestController
@RequestMapping("/api/user")
public class UserProfileController {

    @Autowired
    private UserRepository userRepository;

    @GetMapping("/profile")
    public ResponseEntity<User> getUserProfile(@RequestParam("account_id") Long accountId) {
        // TRUY VẤN LỖ HỔNG: Lấy dữ liệu trực tiếp dựa vào ID người dùng cung cấp trên URL.
        // Kẻ tấn công có thể thay đổi account_id (VD: /api/user/profile?account_id=102)
        // Backend KHÔNG kiểm tra ID này có thuộc về người dùng đang đăng nhập hay không.
        User user = userRepository.findById(accountId).orElse(null);
        
        if (user != null) {
            return ResponseEntity.ok(user); // Trả về thông tin nhạy cảm của người khác
        } else {
            return ResponseEntity.notFound().build();
        }
    }
}
```

### Giải thích nguyên nhân:
Đoạn code trên lấy trực tiếp `account_id` từ URL (query parameter) và dùng nó để truy xuất cơ sở dữ liệu. Mặc dù người dùng có thể đã đăng nhập (với `account_id=101`), họ hoàn toàn có thể thay đổi số trên URL thành `102` để xem thông tin của người dùng khác. Backend đã hoàn toàn tin tưởng vào dữ liệu từ client gửi lên mà bỏ qua bước xác thực quyền sở hữu.

## 3. Code an toàn (Secure Code)

Để khắc phục, chúng ta cần lấy thông tin định danh người dùng từ **SecurityContext** (đã được Spring Security xác thực ở filter bằng Session hoặc JWT), thay vì lấy từ dữ liệu do client gửi lên.

```java
@RestController
@RequestMapping("/api/user")
public class UserProfileController {

    @Autowired
    private UserRepository userRepository;

    @GetMapping("/profile")
    public ResponseEntity<User> getUserProfile(Authentication authentication) {
        // CODE AN TOÀN: Lấy thông tin định danh (username) từ SecurityContext (đã được server xác thực)
        // Client KHÔNG thể giả mạo thông tin trong đối tượng Authentication này.
        String currentUsername = authentication.getName(); 
        
        User user = userRepository.findByUsername(currentUsername);
        
        if (user != null) {
            return ResponseEntity.ok(user);
        } else {
            return ResponseEntity.notFound().build();
        }
    }
}
```

### Nếu bắt buộc phải truyền ID (ví dụ: Admin xem profile của User):

```java
@RestController
@RequestMapping("/api/admin")
public class AdminUserController {

    @Autowired
    private UserRepository userRepository;

    // KIỂM TRA QUYỀN TRUY CẬP: Chỉ cho phép người dùng có role ADMIN (thông qua Spring Security)
    @PreAuthorize("hasRole('ADMIN')") 
    @GetMapping("/user/{id}")
    public ResponseEntity<User> getUserProfileByAdmin(@PathVariable("id") Long targetUserId) {
        
        // Vì đã kiểm tra phân quyền (Access Control) ở annotation @PreAuthorize
        // hàm này an toàn khi lấy ID từ URL để truy xuất dữ liệu.
        User user = userRepository.findById(targetUserId).orElse(null);
        
        if (user != null) {
            return ResponseEntity.ok(user);
        } else {
            return ResponseEntity.notFound().build();
        }
    }
}
```

## 4. Cách phòng chống
- **Deny by Default:** Mặc định từ chối mọi yêu cầu truy cập, chỉ cấp quyền khi đã cấu hình rõ ràng (sử dụng `.anyRequest().authenticated()` trong Spring Security).
- **Không tin tưởng input từ client:** Luôn lấy định danh (User ID, Role) từ hệ thống quản lý phiên (Session, JWT) thay vì Query, Body hay Header do user truyền lên.
- Kiểm tra quyền sở hữu đối với các bản ghi (Record-level access control) trước khi đọc/ghi vào CSDL (ví dụ dùng `@PostAuthorize` hoặc code tay).
- Sử dụng UUID thay vì ID tự tăng (1, 2, 3...) để tránh kẻ tấn công đoán được ID của người khác, tuy nhiên đây chỉ là biện pháp làm chậm kẻ tấn công (Obscurity) chứ không thay thế được việc kiểm soát quyền truy cập thực sự.
