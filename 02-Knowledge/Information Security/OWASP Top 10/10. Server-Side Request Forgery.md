# A10: Server-Side Request Forgery - SSRF (Giả mạo yêu cầu từ Server)

## 1. Khái niệm
SSRF xảy ra khi một ứng dụng web nhận một URL/địa chỉ do người dùng cung cấp và server (backend) trực tiếp gọi (fetch) tài nguyên từ URL đó mà không kiểm duyệt.

Kẻ tấn công lợi dụng việc Server thường có mức độ tin cậy cao hơn để ép Server gửi yêu cầu đến các hệ thống nội bộ (như Database cục bộ, API quản trị nội bộ 192.168.x.x, Metadata của AWS Cloud) - những nơi mà từ bên ngoài internet kẻ tấn công không thể tự kết nối trực tiếp.

## 2. Code ví dụ lỗ hổng (Vulnerable Code)

Giả sử ứng dụng có tính năng "Tải ảnh avatar từ URL".

```java
import org.springframework.web.bind.annotation.*;
import java.net.HttpURLConnection;
import java.net.URL;
import java.io.InputStream;
import java.io.ByteArrayOutputStream;

@RestController
@RequestMapping("/api/image")
public class ImageController {

    @GetMapping("/fetch")
    public byte[] fetchImage(@RequestParam String imageUrl) {
        try {
            // LỖ HỔNG: Chấp nhận mọi URL do người dùng cung cấp
            // Hacker có thể truyền: http://localhost:8080/admin/delete-db
            // hoặc http://169.254.169.254/latest/meta-data/ (để lấy API key AWS)
            URL url = new URL(imageUrl);
            HttpURLConnection connection = (HttpURLConnection) url.openConnection();
            
            // Server backend ĐỨNG RA kết nối thay hacker
            InputStream inputStream = connection.getInputStream();
            
            ByteArrayOutputStream buffer = new ByteArrayOutputStream();
            int nRead;
            byte[] data = new byte[1024];
            while ((nRead = inputStream.read(data, 0, data.length)) != -1) {
                buffer.write(data, 0, nRead);
            }
            return buffer.toByteArray(); // Trả kết quả (file, html...) về cho hacker
        } catch (Exception e) {
            return null;
        }
    }
}
```

## 3. Code an toàn (Secure Code)

Cách hiệu quả nhất để chống SSRF ở mức ứng dụng là sử dụng **Whitelist (Danh sách trắng)** các domain được phép kết nối.

```java
@RestController
@RequestMapping("/api/image")
public class SecureImageController {

    // CHỈ cho phép tải ảnh từ các domain an toàn
    private static final List<String> ALLOWED_DOMAINS = Arrays.asList(
        "images.google.com", 
        "cdn.mycompany.com"
    );

    @GetMapping("/fetch")
    public ResponseEntity<byte[]> fetchImageSecure(@RequestParam String imageUrl) {
        try {
            URL url = new URL(imageUrl);
            String targetDomain = url.getHost();

            // CODE AN TOÀN: Kiểm tra chặt chẽ Domain (Whitelist Validation)
            if (!ALLOWED_DOMAINS.contains(targetDomain)) {
                return ResponseEntity.status(HttpStatus.FORBIDDEN).body(null);
            }
            
            // Đảm bảo chỉ dùng HTTPS
            if (!url.getProtocol().equalsIgnoreCase("https")) {
                return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(null);
            }

            // Thực hiện kết nối khi đã xác minh an toàn
            HttpURLConnection connection = (HttpURLConnection) url.openConnection();
            // ... đọc InputStream ...
            
            return ResponseEntity.ok(data);
            
        } catch (Exception e) {
            return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(null);
        }
    }
}
```

## 4. Cách phòng chống khác (Mức độ mạng lưới)
Trong thực tế, việc viết regex hoặc code để chặn IP nội bộ rất khó và dễ bị lọt lỗi lách luật (như truyền IP dạng Hex, Dec, hoặc chuyển hướng DNS rebinding).
Do đó, các biện pháp infra/mạng thường hiệu quả hơn:

- Cô lập tính năng fetch vào một container hoặc máy chủ ảo riêng biệt (Air-gapped) ở mạng DMZ.
- **Cấu hình Firewall mạng (Egress Filtering):** Chặn không cho máy chủ backend tạo các kết nối ra bên ngoài đến các dải IP nội bộ (localhost/127.0.0.1, 10.x.x.x, 172.16.x.x, 192.168.x.x).
- Vô hiệu hóa việc hệ thống đi theo các đường dẫn chuyển hướng `HTTP Redirect (3xx)`.
