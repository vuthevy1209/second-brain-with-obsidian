# A08: Software and Data Integrity Failures (Lỗi toàn vẹn phần mềm và dữ liệu)

## 1. Khái niệm
Lỗ hổng xảy ra khi ứng dụng sử dụng các phần mềm, đoạn mã, bản cập nhật hoặc dữ liệu được tuần tự hóa (Serialization) từ các nguồn không đáng tin cậy mà không hề xác minh chữ ký, băm mã hoặc kiểm tra tính toàn vẹn của chúng. 

Kẻ tấn công có thể chèn các thư viện nhiễm độc (Supply chain attack) hoặc truyền dữ liệu độc hại để thực thi mã từ xa (RCE). Lỗi kinh điển nhất trong Java ở hạng mục này là **Insecure Deserialization**.

## 2. Ví dụ lỗ hổng (Vulnerable Code) - Java Insecure Deserialization

Quá trình **Serialization** là chuyển một Object Java thành luồng byte để lưu trữ hoặc truyền đi. **Deserialization** là quá trình ngược lại (từ byte thành Object). Nếu ứng dụng đọc luồng byte từ người dùng gửi lên mà giải mã trực tiếp, hệ thống sẽ thực thi mã độc nếu luồng byte đó chứa các Gadget Chain (như lỗ hổng nổi tiếng của thư viện Commons Collections).

```java
import java.io.InputStream;
import java.io.ObjectInputStream;

public class VulnerableDeserialization {

    // Kẻ tấn công gửi một file hoặc dữ liệu nhị phân chứa payload độc hại qua inputStream
    public void deserializeData(InputStream untrustedInputStream) {
        try {
            // LỖ HỔNG: Sử dụng trực tiếp ObjectInputStream để giải mã dữ liệu từ bên ngoài
            // Nếu stream chứa Object độc hại, nó sẽ tự động chạy các method như readObject(), finalize()
            // dẫn đến RCE (Thực thi lệnh hệ điều hành) TRƯỚC CẢ KHI ta ép kiểu Object về đúng class.
            ObjectInputStream ois = new ObjectInputStream(untrustedInputStream);
            
            Object obj = ois.readObject(); 
            
            // Xử lý object...
            ois.close();
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

## 3. Khắc phục an toàn (Secure Code)

### 3.1. Dùng JSON thay thế
Cách tốt nhất là **KHÔNG sử dụng Java Serialization gốc** (`ObjectInputStream`) để truyền dữ liệu. Hãy sử dụng JSON (qua Jackson hoặc Gson). Các bộ phân tích JSON thuần túy (dạng data-only) thường an toàn hơn nhiều.

```java
import com.fasterxml.jackson.databind.ObjectMapper;

public class SecureDeserialization {
    public void deserializeJson(String jsonString) {
        try {
            ObjectMapper mapper = new ObjectMapper();
            
            // CODE AN TOÀN: Jackson chỉ map các trường (fields) thành Object Data thuần, 
            // không tự động khởi tạo và chạy các method nguy hiểm của lớp nội bộ Java.
            User user = mapper.readValue(jsonString, User.class);
            
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```
*Lưu ý:* Khi dùng Jackson, tuyệt đối tránh dùng tính năng kích hoạt đa hình toàn cục (`@JsonTypeInfo` / `enableDefaultTyping()`) nếu không có whitelist chặt chẽ, vì nó cũng gây ra rủi ro tương tự.

### 3.2. Dùng ObjectInputStream có kiểm duyệt (ValidatingObjectInputStream)
Nếu bắt buộc phải dùng ObjectInputStream gốc do hệ thống cũ (Legacy), hãy dùng thư viện `Apache Commons IO` với `ValidatingObjectInputStream` để tạo **Whitelist** chỉ cho phép giải mã các Class an toàn.

```java
import org.apache.commons.io.serialization.ValidatingObjectInputStream;

public void safeJavaDeserialization(InputStream inputStream) throws Exception {
    ValidatingObjectInputStream vois = new ValidatingObjectInputStream(inputStream);
    
    // CODE AN TOÀN: Chỉ cho phép giải mã đúng 1 class cụ thể
    // Mọi class khác (kể cả mã độc) đều sẽ bị từ chối
    vois.accept(com.mycompany.app.User.class);
    
    Object obj = vois.readObject();
    vois.close();
}
```

## 4. Cách phòng chống khác (Mức độ hạ tầng)
- Kiểm tra tính toàn vẹn (Checksum / Hash / Digital Signature) của mọi phần mềm, thư viện CI/CD, docker image tải về từ internet.
- Đảm bảo repo Maven/NPM nội bộ không bị giả mạo.
- Ký tự động mã nguồn và bản build (Code Signing).
