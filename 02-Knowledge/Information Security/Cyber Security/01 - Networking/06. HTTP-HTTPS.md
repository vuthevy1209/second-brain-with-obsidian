# 06. HTTP & HTTPS

## 1. Định nghĩa / Khái niệm cốt lõi
- **HTTP (Hypertext Transfer Protocol):** <mark style="background:#d3f8b6">Giao thức truyền tải siêu văn bản</mark>, nền tảng của World Wide Web. Hoạt động trên port **TCP 80**.
- **HTTPS (HTTP Secure):** Là HTTP nhưng được <mark style="background:#b1ffff">mã hóa bằng giao thức SSL/TLS</mark> để đảm bảo dữ liệu truyền đi an toàn. Hoạt động trên port **TCP 443**.

## 2. Cách thức hoạt động / Thành phần chính

### Kiến trúc Request - Response (Mô hình Client-Server)
- Client (Trình duyệt) gửi một **Request** tới Server.
- Server xử lý và trả về một **Response** (thường chứa HTML, JSON).

### Cấu trúc một HTTP Request
- **Method (Phương thức):** 
  - `GET`: Lấy dữ liệu.
  - `POST`: Gửi dữ liệu (Login form, upload file).
  - `PUT`/`PATCH`: Cập nhật dữ liệu.
  - `DELETE`: Xóa dữ liệu.
- **Headers:** Chứa thông tin cấu hình (`Host`, `User-Agent`, `Cookie`...).
- **Body:** Dữ liệu cần gửi đi (chủ yếu có ở POST/PUT).

### HTTP Status Codes (Mã trạng thái)
- `1xx (Info)`: Đang xử lý.
- `2xx (Success)`: Thành công (VD: 200 OK).
- `3xx (Redirect)`: Chuyển hướng (VD: 301, 302).
- `4xx (Client Error)`: Lỗi phía người dùng (VD: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found).
- `5xx (Server Error)`: Lỗi hệ thống máy chủ (VD: 500 Internal Server Error).

### Tại sao cần HTTPS?
Với HTTP thông thường (Port 80), dữ liệu (kể cả mật khẩu) truyền dưới dạng <mark style="background:#ffb8e0">Plain-text (văn bản rõ)</mark>. Kẻ tấn công có thể dễ dàng dùng Wireshark để đọc. 
HTTPS sử dụng mã hóa bất đối xứng để trao đổi khóa, sau đó dùng mã hóa đối xứng để truyền dữ liệu, đảm bảo 3 tính chất: **Bảo mật (Confidentiality), Toàn vẹn (Integrity), Xác thực (Authentication)**.

## 3. Các công cụ / Lệnh thường dùng
- `curl -v http://example.com`: Kiểm tra chi tiết quá trình request và response.
- `Burp Suite`: Proxy mạnh mẽ nhất để bắt, chỉnh sửa HTTP Request trong Web Pentesting.
- `Postman`: Công cụ Test API (Gửi HTTP requests).
